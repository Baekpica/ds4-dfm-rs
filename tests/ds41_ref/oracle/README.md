# The vendored oracle

`encoding.py` here is the official DeepSeek-V4.1 text/vision encoding
implementation, the file that teaches the DSML format to the model.  It is
the authority for the V4.1 carriage this project serves: tag spellings, the
tools preamble, the parameter type attribute, the effort header, and the
decode side's acceptance shape.

Do not edit this file.  `ref_drive.py` refuses to load it when the digest
differs from its `ORACLE_SHA256`, and that is the intended behavior: the pin
is what keeps a fixture from tracking a quietly edited reference.  When the
operator supplies a new revision, re-read it, re-pin the constant in
`ref_drive.py`, and regenerate the fixtures with `regen_fixtures.sh` in the
same act, so the diff shows both the new reference and its consequences.

The C implementation that once served as a second reference is not vendored
and is no longer consulted: where the two disagreed the disagreement is
recorded in `docs/ds41-dsml-reference-matrix.md` part D, and the oracle is
what binds.
