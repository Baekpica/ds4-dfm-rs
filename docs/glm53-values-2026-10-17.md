# GLM-5.3 values: the artifact's own sampler, and knobs to change it

Unit: the GLM request-omitted values and the level text. Branch
`fix/glm53-agent-args`, 2026-10-17. Everything here is scoped to the GLM-5.3
syntax (`syntax_for_model_id` -> `ModelSyntax::Glm53`, model ids 7 and 17);
the DSML, Qwen and V4.1 paths are untouched.

## What the artifact declares

The served checkpoint states both contracts itself.

| Contract | Source | Value |
| --- | --- | --- |
| Level text | `chat_template.jinja:2-3` | `reasoning_effort` in `['low','high']` is used, **everything else including absent is `max`**, and the line is always written: `<|system|>Reasoning Effort: {{ ... | capitalize }}` |
| Sampler | `generation_config.json` (zai-org/GLM-5.3-Flash@84c6a6a) | `temperature` 1.0, `top_p` 0.95, **no `min_p` and no `top_k` key**, eos 154820/154827/154829 |

Both files are the artifact's own bytes, not a summary:
`tests/fixtures/chat-template/models/glm-uncensored/provenance.json` records
the template as the GGUF's unmodified `tokenizer.chat_template`
(sha256 `34d5ee66...`), and the deployment script agrees --
`install-glm53-uncensored-vq.sh:127 TEMPLATE_SHA=34d5ee66...`. The level line
is therefore always present in a thinking prompt, and a low-effort request is
a real level the template names.

## What the port served before this unit

| Site | Before | Artifact says |
| --- | --- | --- |
| `render.rs` GLM effort text | Low -> `Reasoning Effort: Max` | Low -> `Reasoning Effort: Low` |
| `tok.rs` CLI effort prefix | Low -> no line at all | Low -> `Reasoning Effort: Low` |
| `generate.rs:1766`, `serve_cont.rs:268` | thinking forces 1.0 / top_k 0 / 1.0 / 0.05 over the request | the artifact's values, and an explicit request value must win |
| `parse.rs:18-20` defaults | top_p 1.0, min_p 0.05 | top_p 0.95, min_p none |
| `serve.rs:1248` default level | `ThinkMode::Low` top level | max (the template's else branch) |

Two failures followed from that. A client asking for level `low` -- the level
whose own picker entry reads "Shortest thinking budget; answers fastest" --
was served the **deepest** level instead, which is the opposite of the request;
and every client value for temperature, top_p and min_p was discarded in
thinking, so the 0.95 the client sent never reached the sampler.

## The host the port mirrors, and where this deviates

The newer upstream C host collapses the level deliberately:
`ds4_glm_reasoning_effort_text` (ds4.c:44190) returns `Reasoning Effort: High`
for LOW, MEDIUM and HIGH alike, MAX for MAX, and ds4.h:29 records the choice
("Qwen3.8 reasoning_effort low/medium; other models render them as HIGH").
The older C in this repo goes further and writes nothing for LOW
(`glm53_reasoning_effort`). Neither matches the artifact, and upstream's own
GLM fixture tooling renders the artifact's text instead
(`/data/ds4/gguf-tools/quality-testing/README.md:283`: "For the long GLM
fixtures, render the official `Reasoning Effort: Low` template").

This port follows the artifact: the model's own template is the prompt
contract, and the quality tooling upstream uses to score the same checkpoint
renders the same line. The deviation is named here, measured against the
artifact (the two fixture templates byte-identical to the GGUF's, plus the
generation_config above), and the repo's own C oracle was corrected with it
(`ds4.c:39580-39589`), so the tokenizer parity suite keeps testing one
behaviour instead of two. Nothing else in `ds4.c` changed.

## The change

`parse.rs` gains a GLM value scope, resolved once per process:

    pub struct GlmValues { top_p: f32, min_p: f32, effort: ThinkMode }
    GLM53_DEFAULT_TOP_P = 0.95   GLM53_DEFAULT_MIN_P = 0.0
    GLM53_DEFAULT_EFFORT = Max   (temperature stays default_temperature())

| Knob | Default | Scope |
| --- | --- | --- |
| `DS4_SERVER_DEFAULT_TEMP` | 1.0 | every family (pre-existing) |
| `DS4_SERVER_DEFAULT_TOP_P` | 0.95 | GLM |
| `DS4_SERVER_DEFAULT_MIN_P` | 0.0 | GLM |
| `DS4_SERVER_DEFAULT_EFFORT` | max (`low`/`high`/`max`) | GLM |

The shape is ds41's (`parse.rs` `resolve_min_p` on `optimize4`: parse, validate,
report, fall back -- never clamp): a value outside `[0,1]`, a non-number, or an
effort name outside the artifact's three is reported once at startup and the
artifact value is used. The bin sets the scope when the opened model is GLM
and prints the effective line:

    ds4-server-rs: GLM values: temperature=1 top_p=0.95 min_p=0 effort=Max

`fixed_thinking_sampling(syntax)` now names the exception: every family keeps
the port's fixed thinking tuple except IQuest (as before) and the GLM scope,
which takes what the request resolved to -- the host's rule for the same case
(ds4_server.c:13951-13959: "an explicit request value ... must win"), applied
to the values this artifact declares.

## Consequences to know

- An explicit `temperature: 0` in thinking now really is greedy for GLM. The
  deployment script's smoke request sends exactly that
  (`install-glm53-uncensored-vq.sh:600`), so the smoke call changes meaning:
  it was served at 1.0 and now takes the greedy path (`generate.rs:1823`
  admits the eager-greedy segment only at `temperature <= 0`).
- The request-omitted default level moves from low to max. Nothing visible
  changes for a request that names no level (low rendered as `Max` text
  before), but the tool-turn reasoning cap does: `agent_turn_reasoning_cap`
  (dsml.rs:628) reads 512 at max against 64 at low, so a bare request with
  tool results may reason longer before the server forces the think close.
  A client that names its level, as this deployment's does, is unaffected.

## Limits

- The level text is not a knob: it is the template's own output.
- `medium` and `minimal` stay aliases of Low in the shared wire vocabulary, so
  a client sending them gets `Reasoning Effort: Low`. The template would have
  read them as max. Recorded, not fixed: the shared mapping belongs to every
  family, and no client in this deployment sends them.
- The values are a deployment setting read once per process, as ds41's are.
- Whether the artifact values reduce the recorded 2026-10-15 loop (min_p 0.05
  pruning the think-close token) is not measured here; the knobs exist so the
  live comparison needs no rebuild.
