# Qwen image latency and determinism (2026-09-07)

Tested on one DGX Spark GB10, driver 610.43.02, CUDA 13.3.73, with
`Baekpica/Qwen3.8-Flash-Next-Mixed-Quant-SSD-PLE-GGUF`, specifically
`MQ-Q5-SSD-PLE-BF16`. The baseline is the actual serving binary at
`c3dfb36`; `main` merge `efe5c3b` has the same tree. The worker uses the
Rust host and native CUDA kernels.

The suite covers new screenshots, documents, a photograph, a small image,
and four images in one request. Agent follow-ups are measured separately:
an image already covered by restored KV does not need the vision encoder.
This is a fixed regression suite, not a general vision accuracy benchmark
or an estimate of every agent's workload mix.

## Changes and numerical evidence

The original screen trace spent 958.1 ms across 27 vision-attention calls,
within a 1,056.4 ms span from the first to last attention call. Its API
TTFT was 1,819.3 ms under nsys. NCU identified the load/store instruction
pipe as the bottleneck (94.7% of peak sustained), guiding K/V read reuse.

The new attention kernel handles two queries per warp and sixteen per
block, reusing K/V registers between queries. The 32-key shared-memory
tile, per-key dot reduction, online-softmax order, and value accumulation
order are retained. Explicit FMA association preserves the old rounding.
There is no N-by-N score allocation, downsampling, token dropping, or
reduced attention. The arithmetic still scales quadratically with patches.
The paired kernel is enabled for the model's 72-value heads and at least
512 total patches. Small inputs and other head widths keep the old kernel;
blocks spanning image boundaries use the original per-row helper.
`DS4_QWEN_VISION_LEGACY=1` is a diagnostic switch for the old tiled kernel.

During full-model checks, the old vision encoder failed its own repeated
forward comparison. Compute Sanitizer localized a shared-memory race in
LayerNorm: `red[0]` could be overwritten with a variance partial before all
warps had read the mean. Commit `e89b121` adds the missing barrier. The
public regression fixture reports two race errors and a repeat mismatch
before the fix, and zero hazards after it; both 1,152- and 4,608-value norms
pass 64 repeats against an independent F64 reference (max error < 4.1e-7).
This correctness fix can change image outputs relative to the previously
nondeterministic encoder. It is not claimed to preserve those old outputs.

With LayerNorm fixed on **both** attention paths, five actual-model cases
(screen, document, photo, large, four-image) pass two legacy and two paired
forwards each: every image-feature float, all 248,320 frontier logits, and
the first greedy token are byte-identical across paths and repeats. The
model test asserts at least 512 patches so it cannot accidentally validate
only the small-input fallback. The model-free attention fixture covers
512/1,031/3,072/8,193 rows, ragged/empty image segments, tail blocks, and
other head widths, with exact old/new comparison plus sampled F64 checks.

NCU's isolated 3,072-patch attention measurement is 36.252 → 26.411 ms
(-27.1%). This kernel measurement is separate from the API results below.

## API latency protocol

Production settings: context 262,144, two banks, 8,192-token prefill chunks,
2,048 MiB SSD-PLE cache, 16 PLE workers, MTP draft 2, continuous lane,
coalescing width 2 / 16,384 tokens / 20 ms, and 32 GiB disk KV. The same
resident VMM owner supplies all workers; only one worker runs at a time.
Host memory is monitored with nvtop/htop and the existing external guard.

Each suite starts a fresh worker with an empty disk-KV directory, then
sends small, screen, document, photo, large, and multi in that fixed order.
Every timed request reports `cached_tokens=0`. PLE and allocator state can
warm between requests in a suite, identically in all variants; these are
not six independent cold model boots. Temperature is zero, thinking is
disabled, and `max_tokens=1`. TTFT is the server's `timings.ttft_ms`; client
wall time includes HTTP and response serialization as well. Neither metric
is decode throughput.

Three variants were interleaved A/C/B/B/C/A/A/C/B: A is the original
serving binary; C has the LayerNorm fix with legacy attention; B has both
changes. Each variant has three fresh workers, with no concurrent build,
profiler, or competing model workload during timing. Report per-case
medians, without averaging unrelated agent workflows.

| Input | Patches / prompt tokens | Original TTFT | Norm fix, legacy attention | Both changes | TTFT reduction |
| --- | ---: | ---: | ---: | ---: | ---: |
| Small dashboard (256 × 256) | 256 / 93 | 0.2748 s | 0.2749 s | 0.2747 s | within noise |
| Screenshot (1024 × 768) | 3,072 / 797 | 1.8244 s | 1.8251 s | 1.5637 s | 14.3% |
| Invoice (1536 × 1024) | 6,144 / 1,565 | 5.4330 s | 5.4315 s | 4.3985 s | 19.0% |
| Photo (512 × 507) | 1,024 / 285 | 0.5583 s | 0.5572 s | 0.5308 s | 4.9% |
| Large screen (1920 × 1080) | 8,160 / 2,069 | 8.6347 s | 8.6301 s | 6.7968 s | 21.3% |
| Four images (fixed order) | 10,496 / 2,659 | 7.1737 s | 7.1732 s | 5.8290 s | 18.7% |

The small-input dispatch is unchanged. The norm-only control tracks the
original latency closely; the improvement comes from paired attention.
Client wall-time medians show the same trend. Full samples are in
[`qwen-images-2026-09-07.csv`](benchmarks/qwen-images-2026-09-07.csv).
The original server binary SHA-256 is
`5c78c7f7184ab3f9fb5d34efaf878650df37cc24b136958e9bf1b7810a288a52`;
the tested final binary is
`e81704f7a40bbc278b137dee0f18976527e415ec477937f8fa32ed4fc14462ec`.

Fixtures and their SHA-256 hashes are recorded in each benchmark JSONL.
The PNGs are synthetic task dashboards and an invoice; the JPEG is the
public-domain Apollo 17 Earth photograph. See
[`tests/fixtures/qwen-images`](../tests/fixtures/qwen-images/README.md).

## Agent and text regression checks

All twelve functional requests pass on the original server, norm-fixed
legacy attention, and paired attention. The norm-fixed legacy and paired
paths return identical generated text and function arguments in all twelve
cases (transport IDs excluded). These are single functional runs, separate
from the latency medians above; raw results are in
[`qwen-image-agent-2026-09-07.csv`](benchmarks/qwen-image-agent-2026-09-07.csv).

- OCR reads Failed **3** and invoice total **$385.00**; the photo is **Earth**.
- An immediate screenshot follow-up returns **Queued 12**, reusing
  **800/828** prompt tokens. TTFT is 189.7 / 193.7 ms with legacy / paired
  attention. The encoder is skipped, so no image-kernel speedup is claimed.
- Same geometry with Failed changed to **9** returns **9** and stays cold.
- OpenAI Chat, Responses, and Anthropic native image schemas all pass.
- A four-image agent request with one tool and `tool_choice="required"`
  returns `record_observation({"failed_tasks":3,"invoice_total":385})`.
  The tool-result follow-up returns the same summary and reuses
  **2,990/3,045** tokens. Named forced tool choices are not supported by the
  existing API; this test uses its supported required-tool form.
- Two clients synchronized at a barrier produce the correct screenshot and
  invoice answers, with `served=2 fallback=0` in the continuous lane.
- After a new-worker restart, a saved image conversation restores from disk,
  reuses **824/846** tokens, and returns **3** (TTFT 216.8 ms).

Cache reuse assumes the relevant bank or disk entry remains available. A
separate diagnostic that inserted two unrelated image turns before the
follow-up evicted the live screenshot state and recomputed the image;
consecutive-turn and evicted-state timings must not be combined.

The original Italian prose (`promessi_sposi.txt`) protocol was preserved:
one fresh `ds4-bench` process per cold single-shot 8,192/65,536-token prefill,
32 greedy output tokens, 8,192-token chunks, 2 GiB PLE and 16 workers,
same resident owner. Three runs each, interleaved A/B/B/A/A/B:

| Text workload | Original prefill | Updated prefill | Original / updated steady decode |
| --- | ---: | ---: | ---: |
| 8,192 tokens | 1501.10 tok/s | 1499.79 tok/s | 24.61 / 24.60 tok/s |
| 65,536 tokens | 1645.00 tok/s | 1643.63 tok/s | 24.16 / 24.19 tok/s |

Both full-vocabulary frontier-logit dumps and all 32 greedy token IDs are
byte-identical at 8K and 64K. Text throughput is effectively unchanged.
[`qwen-image-text-2026-09-07.csv`](benchmarks/qwen-image-text-2026-09-07.csv)
contains the individual samples; steady decode excludes the first call.
No long-context image-quality claim follows from these text-only checks.

## Reproduction

Build with the checkout's CUDA configuration, then run the model-free
checks (no GGUF required):

```sh
make -j4 ds4-server ds4-bench tests/test_qwen_vision_norm \
  tests/test_qwen_vision_attention tests/test_qwen_vision_model
./tests/test_qwen_vision_norm
compute-sanitizer --tool racecheck --error-exitcode 3 ./tests/test_qwen_vision_norm
./tests/test_qwen_vision_attention
```

For the full model, set the same IPC owner and production environment as
the worker above, stop the worker, and run one native fixture at a time:

```sh
./tests/test_qwen_vision_model "$MODEL" tests/fixtures/qwen-images/screen.png
./tests/test_qwen_vision_model "$MODEL" tests/fixtures/qwen-images/document.png
./tests/test_qwen_vision_model "$MODEL" tests/fixtures/qwen-images/photo.jpg
./tests/test_qwen_vision_model "$MODEL" tests/fixtures/qwen-images/large.png
./tests/test_qwen_vision_model "$MODEL" tests/fixtures/qwen-images/small.png \
  tests/fixtures/qwen-images/screen.png tests/fixtures/qwen-images/photo.jpg \
  tests/fixtures/qwen-images/document.png
```

Against each fresh worker/empty KV directory, use the fixed HTTP suite:

```sh
python3 tests/bench_qwen_images.py --output /tmp/qwen-images-run1.jsonl
```

Restart the worker before repeating. To isolate attention from the norm
correction, compare the same binary with and without
`DS4_QWEN_VISION_LEGACY=1`. Preserve all other settings and fixture bytes.
The benchmark client rejects cached timed prompts and existing output
files, and does not manage the server or delete caches.

Local raw evidence is under `scratch/qwen-image-opt-20260907/`: latency
JSONL/meta/stats files, `model-*.log`, `attention-stable.log`, norm racecheck
logs, nsys/NCU reports, agent responses, and text CSV/logit dumps. Large
profiles and model-derived tensors are not committed.
