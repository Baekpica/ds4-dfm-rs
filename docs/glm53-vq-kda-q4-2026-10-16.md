## Target and reference

After [FP8 projection fusion](glm53-vq-fp8-2026-10-16.md), the retained
1,984+32-token trace spends 1.190125 s of 4.361506 s decode in KDA BF16
Q/K/V/O GEMVs: 27.29%. Q/K/V share shape `[8192,4096]`; output uses
`[4096,8192]`. These 136 matrices read 9,126,805,504 logical weight bytes
per generated token. This is not a DRAM-counter measurement.

An actual layer-zero replay of production BF16/cuBLAS measures Q at
275.641 µs and output at 282.634 µs, close to the in-model shape means
271.907/278.145 µs. It rotates at least 64 MiB of weights, uses saved
activations, 16 warmups, 512 repeats and the production 32 MiB cuBLAS
workspace. NCU records Q at 164 registers, 24.94% occupancy, 1.01% L2
hit rate and 2.196 GHz. CUDA/cuBLAS are the system 13.4.92/13.8.0.4 libraries.

The already-qualified [Q4 cooperative-load path](glm53-vq-q4-stream-2026-10-16.md)
measures these shapes at 83.51/85.37 µs. Its Q input is the saved activation;
its output-projection input is synthetic. These are target hints, not a
fully input-matched end-to-end comparison. No unchanged primitive gate
was repeated. YoungAi `7fb26cc`'s `cuda_v41_q4k.inc.cu:29-179` motivates
contiguous CTA loads and register block headers. The measured GLM staging
path beats double buffering; the latter remains diagnostic. VQ prefill
continues to use its separately qualified asynchronous double buffer.

## Independent V/O result

Sixteen additional text tasks were frozen before inspecting the V/O outputs.
Two fresh processes use the same `8475abc12ff7fa0f336b985b39ffd3060f7a49f53aa4170cdac7fdd6ff798198`
quality executable and identical runtime-library mappings. Over 197 finite
target positions, paired NLL changes +0.00430 nat; case-bootstrap 95% interval
is [-0.01234,+0.01910]. Eleven generated answers are identical. Both code
functions pass empty, duplicate, negative and zero integer inputs without
mutation; JSON values, key order, the tool-result name and exact stop answer
also hold. These are text fixtures, not live tool or multi-turn tests.

Two Korean cases prevent adoption. For a reservation correction, the original
repeats context but reaches “금요일 2명”; the candidate repeats the question
and stops without answering. Another candidate answer adds the prompt and a
stray `</think>` before its otherwise correct fact. This is a task/output
regression, not rejection for different token strings or a fixed RMS bound.
The original's separate language, repetition and truncation failures remain.

The initial decision retained original nonexpert precision and deferred
both speed campaigns. The later user selection above supersedes that
decision. The isolated Q4 dot advantage remains separate from measured
whole-model speed; current optimization reuses the qualified cooperative
Q4 implementation and the existing conversion evidence.
Conversion provenance, target counters, raw receipt identities and both
quality comparisons are in the [evidence](evidence/glm53-vq-kda-q4-2026-10-16.json).

## Execution boundary

Current source is `6b5a00e2`; all accepted VQ MMA, direct expert, FP8 fusion
and Q4 staging paths are enabled. Context is 2,048, chunk 512, MTP/capture
off, one in-process VMM owner, with unchanged 300–2,200 MHz clock policy.

Text screens use the existing forced-thinking-off interface: GLM's source
template starts `<think>` with maximum reasoning effort, and the host
appends `</think>`. They do not evaluate ordinary source reasoning-mode
generation. The independent original control already emits English analysis
for one Korean request and repeats context in two others, reaching the
96-token cap. Keep these baseline failures separate from new Q4 regressions;
they alone do not identify artifact loss or a runtime defect.

The first 136-matrix quality attempt stopped during loading: PSI full
reached 20.24% while 70.53 GiB remained available. It produced no inference
evidence. The retry uses the documented PSI telemetry mode, retaining
104/100 GiB cgroup max/high, a 12 GiB reserve/trip floor, no scope swap and
a 1,800 s deadline. This loading failure remains recorded; the allocator
stall's underlying cause is unproven.

These experiments do not qualify 8K, graphs, MTP, image input, live tool
protocol, multi-turn cache reuse, banks, snapshots or disk KV.
