# Gemma-4 Phase 3 round — the vocabulary head, RoPE and the router (2026-11-03, late)

Round starts from `f64d3d66` on `feat/gemma4-family` (the handoff commit
after the VQ-GEMM decode measurement). Artifact
`/data/vq-artifacts/gguf-family-it-r8` (R13+8 dense-VQ family build); one
RTX 4070 SUPER, 56 SM, `sm_89`, driver 610.43.03, CUDA 13.3.73, 12282 MiB,
max SM clock 3105 MHz. One model process at a time; device-resident
(`DS4_CUDA_COPY_MODEL=1`, 9.37 GiB copied). Prompt `/tmp/g4-bench-256.txt`
(256 tokens), ctx 256, eight greedy tokens. The four earlier options
(`DS4_GEMMA4_VQ_PREFILL`, `ATTN_PREFILL`, `ATTN_FAST`, `Q8_BATCH`) are on in
every arm of this round.

The owner's constraint for the round: the family's new code is Gemma-only
(`cuda/gemma4_primitives.cuh`, `cuda/gemma4_head.cuh`,
`cuda/gemma4_router.cuh`, `ds4_gemma4_gpu.cuh`, `ds4_gemma4_graph.inc`), and
the shared GLM kernels are not the Gemma implementation. The design review
that shaped the round is `agy_review_phase3.md` (Gemini 4 Argon, session 14).

Two facts decided the round. The rope is 5.5 ms per step because one thread
per (row, head) runs 64 to 128 serial FP64 `cos`/`sin` pairs on a card whose
FP64 pipe is 1/64 of FP32, with only 16 (query) or 8 (key) threads active.
The router's top-8 is 2.88 ms per step because one thread scans 128 experts
eight times with an inner taken-scan. The head is not a target: 1.47 GB in
3.10-3.16 ms per call is 466-474 GB/s, 92-94 percent of the card's 504 GB/s
(the review's 177 GB/s is cuBLAS's number for the GLM head, not this
kernel's).

## The four units

### A. Fused RMSNorm + RoPE (`DS4_GEMMA4_FUSE_ROPE=1`)

`cuda/gemma4_primitives.cuh:g4_rms_rope_kernel`, one block per (row, head),
256 threads. The reduction, the rounding and the staged row are
`g4_rms_kernel`'s; the rope pairs then rotate from shared with
`g4_rope_kernel`'s exact expression, including the float cast of the angle
and the two roundings per output. The sliding geometry rotates all 128 pairs;
the full geometry rotates pairs 0-63 of 256 and copies the rest. The query
norm + rope and the key norm + rope replace two launches and two row passes
each; the value norm stays separate.

Gate (same binary, option off/on): tokens identical
`[6113, 1698, 236761, 28333, 506, 877, 6910, 3136]`, frontier logits
relL2 0.0, max 0, same argmax and top-5. Off 557.56 prefill / 26.22 decode;
on 613.63 / 32.10; TTFT 42.3 -> 32.6 ms.

### B. Parallel router top-k (`DS4_GEMMA4_ROUTER_PAR=1`)

`cuda/gemma4_primitives.cuh:g4_router_kernel<PAR>` replaces the one-thread
scan with k block max passes: every thread carries its probability and index
through the same tree (`b > a || (b == a && ib < ia)` keeps the lower index
on ties), the winner is marked used, and the k values are summed in pick
order. The selected ids, the weights and their order are the serial scan's.

Gate: tokens identical, frontier logits relL2 0.0. Off 473.18 / 27.16; on
624.45 / 33.60 (the off arm's prefill was host-noisy; the interleaved table
below is the timing of record).

### C. The family's own vocabulary head (`DS4_GEMMA4_HEAD_GEMV=1`)

`cuda/gemma4_head.cuh:g4_head_gemv_kernel<COLS, SOFTCAP>`, a persistent grid
(4 blocks per SM, 256 threads, one warp per row, grid-stride over the
262144 rows), the input row staged once per block in shared, `uint4` per
lane at stride 256 columns, `__ldcs` streaming, the same XOR reduction as
`glmvq_bf16_dot`'s split==1 sequence, and `g4_softcap_kernel`'s three
roundings fused into the lane-0 epilogue. The per-lane column set, the FMA
order and the reduction are unchanged, so the logits are the shared
kernel's bit for bit; the head no longer runs sibling code and the separate
1 MB softcap pass is gone.

Gate: tokens identical, frontier logits relL2 0.0. Off 329.46 / 34.11; on
626.70 / 34.82 (the off arm's prefill was host-noisy). The head itself is at
the roofline; the unit buys ownership and the fused softcap, not bandwidth.

### D. The family's own router dot (`DS4_GEMMA4_ROUTER_DOT=1`)

`cuda/gemma4_router.cuh:g4_router_dot_kernel`, 128 blocks (one per expert),
256 threads, the shared BF16 dot's split==8 mapping and partial-sum order:
warp part p covers columns (p*32 + lane)*8 + k*2048, each lane accumulates
its eight products per uint4 in order, the warp reduces by XOR, and thread 0
sums partial[0..7] left to right and rounds once. The router projection no
longer runs `glmvq_bf16_dot`; prefill (rows > 1) keeps the batched path.

Gate: tokens identical, frontier logits relL2 0.0. Off 540.15 prefill /
33.10 decode; on 596.18 / 35.30. The pair is not interleaved, so the gain
is small and the exactness is the point; the router projection no longer
runs a sibling kernel.

## What still runs shared code

The Q4_K projections (`glmvq_q4_stream`, `glmvq_q4_small`, 3.29 ms/step,
8.2 percent of the decode) and the dense Q8_0 down (`matmul_q8_0_preq_warp8`,
0.48 ms/step) are still sibling kernels. They are the next ownership unit,
not part of Phase 3's list. The expert VQ GEMVs (`g4_vq_gemv_*`) and the
prefill GEMM (`gemma_vq_prefill.cuh`) are already Gemma-only.

## Reproduce

```sh
cd /data/ds4-gemma4
make cuda CUDA_ARCH=sm_89
bash /tmp/g4-rope-ab.sh        # A, exactness pair
bash /tmp/g4-router-ab.sh      # B
bash /tmp/g4-head-ab.sh        # C
bash /tmp/g4-routerdot-ab.sh   # D
bash /tmp/g4-phase3-timing.sh  # interleaved timing
```

Each exactness script runs the same binary with the option off and on,
dumps the frontier logits, compares the tokens byte for byte and the logits
with `/tmp/g4-cmp.py`. The Phase 3 options stay default-off; the handoff
records the measured gain and the owner decides when to make them the
default.
