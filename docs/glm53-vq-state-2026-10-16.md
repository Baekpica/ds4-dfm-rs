# GLM VQ persistent state

VQ now uses the common native bank and snapshot APIs. Its payload has a
separate family tag, so BF16 VQ pool state cannot be restored as MXQ state.
Restores also reject a dense-only context crossing into the sparse-indexer
regime: a context at or below 2,048 never built the required pools.

Banks own their KDA recurrence, convolution tails, latent history, index
pools and logits. Serialized bank forwards share VQ handles and execution
scratch; bank zero releases that workspace after the other banks. This
avoids both duplicate workspace and a shallow-copy double free. Arithmetic,
weights and numerical dispatch are unchanged.

The active artifact remains `GLM-5.3-Flash-VQ-Q4K-KDA-GGUF`: 34 KDA layers
have Q/K/V/O in Q4_K, totaling 136 matrices. Other weights retain their
source bytes. Manifest SHA256:
`6ea4054b04cfb1bd2e26db318e022a5918b49c8002d7d5e1cf17e502a074a044`.

One fresh process loaded one model owner on GB10. It used eager CUDA,
context 8,192, chunk 1,024, a 6,147-token raw prompt, two persistent banks,
and three forced token-100 outputs per bank request. MTP was disabled.

| Gate | Result |
|---|---|
| Session snapshot after advancing beyond token 4,097 | Entire payload restored byte-exactly |
| Session disk restore after a different continuation | Entire payload restored byte-exactly |
| Dense 2K payload into an 8K session | Rejected; position and logits unchanged |
| Unrelated request in the second bank | First bank payload unchanged |
| Fork from a 4,097-token checkpoint after the source advanced | 4,097 cached tokens; full state matches the same-state serial continuation |
| Disk payload imported into the other bank | Entire payload restored byte-exactly |
| Continuation from the imported payload | 6,149 cached tokens; full state matches the same-state serial continuation |

The checkpoint falls inside a four-token pool. Comparisons include carried
KDA state, latent keys, complete pools, partial tails, tokens and logits.
Byte identity checks restore plumbing and identical execution widths; it
does not impose bit identity on different arithmetic or quantization paths.

The gate passed in 39.501 seconds after loading; total guarded process time
was 263.917 seconds. These include snapshot I/O and are not throughput or
TTFT measurements. Minimum system available memory was 33.023 GiB. Busy
SM samples were 2,184–2,190 MHz, preserving the 300–2,200 MHz policy. The
guard used max/high/reserve 104/100/12 GiB, timeout 1,800 seconds and
telemetry-only PSI. All task model processes exited successfully.

The executable SHA256 is
`99ff2b05770128f9e8758bafc6ab856f99b9bb84abe55ba1db880fbe28c9339e`,
built from `48a18e5b` plus the recorded source changes. Actual loaded
libraries were driver 615.71.09, CUDA runtime 13.4.92 and cuBLAS/cuBLASLt
13.8.0.4. The [evidence](evidence/glm53-vq-state-2026-10-16.json) includes
the command, source hashes, build, logs, clocks and memory samples.

Focused regressions first reproduced missing VQ payload identity and bank
ownership. After the fixes, 12 Rust payload tests, two VQ capability tests
and the native payload/bank fixtures passed. Initial fixture/import/token
buffer compilation errors are retained; the first live model run passed.
Apple guards later excluded unsupported VQ fixture cases without changing
the tested Linux path. Closed packing, numerical, quality and performance
gates were reused; this feature did not change their execution path.

Capabilities now report banks, partial reuse, snapshots and disk payloads
as present. HTTP serving, overlapping requests, disk-cache policy,
MTP, captured decode and vision remain unqualified. This proves two serially
executed banks, not parallel GPU batching. Public qualified limits remain
unset until the corresponding serving workloads pass.
