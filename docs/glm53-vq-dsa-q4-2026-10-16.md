# GLM VQ selective DSA Q4_K assessment

Keep the current 136-matrix KDA Q4 baseline. Adding DSA Output/Q-B gives
an isolated speedup, but the four whole-model observations do not establish
a repeatable gain beyond run variation. The candidate is not adopted.

This experiment changes only Output and Q-B in the eleven DSA layers
3, 7, ..., 43. The active KDA Q4 artifact has 136 Q4 matrices; the candidate
has 158. All other 39,840 tensor entries, including routed/shared experts,
codebooks, KV-B, indexer, controls and output head, are unchanged.

## Why these projections

The retained [8K profile](glm53-vq-sparse-2026-10-16.md) attributes 5.143%
of decode wall time to DSA Output and 1.966% to Q-B. Q-A and KV-A contribute
only 0.504% and 0.203%. Source call order and every launch's grid/block
identify the 179 FP8 projections per token in the existing trace.

The existing Output NCU capture reports 37 registers, 97.53% achieved
occupancy and 16.63% L2 hits at 271.072 microseconds. The current FP8/Q4
operators match their previously qualified source hashes, so those counters
and numerical checks remain applicable.

Q4_K/FP8 describe weight storage, not the activation format between layers.
Both paths use the common FP32 buffers and BF16 projection boundaries.
Adjacent layers do not convert activations into the next weight format.
Any gain must come from less weight traffic or a faster operator. Wide
Q4 prefill does introduce Q8_1 input quantization for MMQ; choosing Q4 for
more matrices does not automatically share that preparation.

KV-B remains BF16. In `ds4_gpu_gvq_dsa`, another weight format currently
selects full-prefix expansion before the latent-attention dispatch. A
blanket Q4 conversion would therefore lose the retained fast path.

## Target screen and artifact

Three fresh processes per format and shape replay actual layer-11 weights
with identical synthetic BF16 inputs, 512 measured iterations and at least
64 MiB of rotating weights. Existing libraries are reused; no native build
or repeated arithmetic proof is needed.

| Matrix [output,input] | FP8 median, microseconds | Q4 median, microseconds | Latency change |
|---|---:|---:|---:|
| Output [4096,16384] | 277.069 | 202.971 | -26.74% |
| Q-B [16384,1536] | 100.272 | 80.395 | -19.82% |

These are isolated screens, without in-model routing/intervening kernels
or active-clock telemetry. FP8/Q4 warmups are 16/32 iterations, excluded
from timing. Applying the isolated ratios to the retained trace predicts
about 1.76% decode latency reduction; it is not a whole-model result.

`tools/glm_vq_select_q4.py SOURCE DONOR OUTPUT --select names.json` copies
selected, original-derived Q4 payloads from an existing donor. It checks
source revision, parent hash, shape, FP8 scale identity and copied payload
checksums. Rewritten parts keep 128-byte alignment; untouched files use
hardlinks. It neither requantizes weights nor modifies source files.

The candidate is `GLM-5.3-Flash-VQ-Q4K-KDA-DSA-OQB-GGUF`, manifest
`173569065f7e29244452bc1054d81965d262b70b5c5d540ac6a15916179a902a`.
Its donor is the existing nonexpert KeepHead artifact, manifest
`d16712edb7940dd070873d7aa660f7731c036605484a1bc54155e5f5c802fe47`.
The unchanged control is `GLM-5.3-Flash-VQ-Q4K-KDA-GGUF`, manifest
`6ea4054b04cfb1bd2e26db318e022a5918b49c8002d7d5e1cf17e502a074a044`.
Selected logical weight payloads fall from 968 to 544.5 MiB per token;
this is not measured DRAM traffic.

Four focused CPU selection checks passed. Review then found that selecting
from an artifact already containing `q4k-selection.json` could overwrite
the source report through a hardlink. A failing-first regression reproduced
that issue; excluding the inherited report before copying passed the new
check. The measured candidate's source had no prior report and was
unaffected. Its exact assembly script is retained separately from the
subsequently fixed tool.

## Whole-workload method

Fresh-process ABBA uses 7,936 raw code input tokens plus 128 forced
non-EOS greedy tokens, context 8,192, chunk 1,024 and MTP/capture off.
Each process uses one VMM owner; OS file-cache state is inherited.
The executable, compiled source snapshot, actual loaded libraries and
retained kernel switches match. Only the artifact differs; quantization
may change routing and logits, so cross-artifact bit equality is not a
quality criterion.

The executable SHA is
`4423f128faaeb2fa29dc4b34845395128e2ee3be64b687720090b7b15994c42d`.
Receipts distinguish its compiled snapshot from the later state-only
checkout. Guards use 104/100 GiB max/high, a 12 GiB reserve, 1,800 seconds
and PSI telemetry. The 300–2,200 MHz clock policy is unchanged.

Phase sums and compute TTFT are inferred from rounded benchmark rates;
they exclude loading and are not HTTP TTFT. Whole-process times are
recorded separately. Broad quality, MTP, vision and live API behavior are
outside this artifact-selection experiment.

## Results and decision

| Artifact | Run order | Prefill tok/s | Decode tok/s | Phase sum, s |
|---|---:|---:|---:|---:|
| KDA Q4 control | 1 | 422.52 | 16.57 | 26.507 |
| Add DSA Output/Q-B Q4 | 2 | 420.18 | 16.62 | 26.589 |
| Add DSA Output/Q-B Q4 | 3 | 424.25 | 16.81 | 26.320 |
| KDA Q4 control | 4 | 414.60 | 16.67 | 26.820 |

Median prefill is 418.56 to 422.215 tok/s (+0.87%); decode is 16.62 to
16.715 tok/s (+0.57%). Median phase time falls 0.78%. Candidate decode
varies 1.14% between its two runs, and the first candidate phase is slower
than the first control. These observations overlap; a small gain remains
possible but unproven. This is not a fixed percentage rejection threshold.
The isolated screen cannot explain the remaining difference without an
in-model target comparison; cache interactions and routing are not measured
causes here.

All processes exit successfully, with busy SM clocks 2,184–2,190 MHz.
Process wall times in order are 222.131, 222.403, 213.614 and 222.152 s.
Minimum system available memory is 38.13 GiB; candidate minima are
38.68/38.51 GiB. This campaign does not trace peak device allocation; the
unchanged control's prior peak remains 78.492 GiB for its recorded run.

Each run has 1,408 latent-attention calls. Candidate direct FP8 calls fall
from 22,912 to 20,096, confirming that the selected projections changed
path without losing latent attention. All 154,880 frontier logits are
finite. The first pair's generated IDs match, with frontier RMS difference
0.314790; that is an observation, not a quality pass. Actual prefill MMA
work items change from 132,099 to 132,004 with routing.

Before measurement, five text cases were frozen for a conditional quality
assessment. It was not run because whole-workload adoption was not
established. No old quality rejection was reopened. The active artifact
and production kernels remain unchanged; the final control also supplies
a fresh whole-workload observation of the retained baseline.

[Evidence](evidence/glm53-vq-dsa-q4-2026-10-16.json) records the target,
artifact assembly, source and library identities, four runs, selector
regressions and the unrun quality scope. No additional build, unchanged
numerical proof or full-model run is required to close this experiment.
