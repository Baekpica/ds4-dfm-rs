# IQuest-Q1 on GB10

The integration passes bounded actual-weight prefix, serial/MTP, ring-wrap,
bank-state and payload-recovery checks. Thinking-mode HTTP reuse/restart
passes after two host fixes; some warm/cold reasoning text still differs.
Earlier disabled-thinking format/output failures remain failures. Embedded
MTP is slower in the matched benchmark. Serial/continuous buffered/SSE
protocols and two concurrent requests pass. These results establish no
general context/bank limit or 512K serving qualification. The
[compact evidence](2026-10-01-iquest-q1-gb10.json) records the receipts.

## Canonical owner and memory

One VMM owner serves all workers, with `--scope base --reserve-gb 28`
and all three aligned repacks disabled. Its 91 canonical ranges contain
87,975,869,440 logical bytes (81.934 GiB), allocated as 88,097,161,216
bytes (82.05 GiB). Actual-weight workers import that allocation and report
zero owned canonical, derived and registered-host weight bytes. All
recorded memory censuses have zero faults. Matching-model derived manifest
records reject before any import.

At context 8192/chunk128, the first-bank/session tensor quote is
1,101,758,336 bytes; each additional bank is 1,025,709,056 bytes. Eight
lazy partial checkpoints add up to 4,501,110,784 bytes. These exclude
common CUDA/MMQ scratch, allocator overhead and host/driver headroom.
Disk checkpoints do not reduce active-bank KV allocation. See the
[family guide](../iquest-q1.md#memory-contract) for the owner command and
separate configured 512K estimates.

## Completed correctness checks

Serialized model-free workspace tests after the host fixes pass **1464**,
with **12 ignored** and zero failures across 83 suites. Formatting and
Clippy checks pass. The earlier integration run passed 1461 tests; the
three added regressions cover serial/continuous thinking sampling and
reasoning-bearing cache retirement/persistence. The final qualification
guard passes 97 focused serving/integration/doc checks. The standalone
HTTP harness passes 26 model-free wire tests. The real vocabulary passes 534
tokenizer cases and four rendered chat vectors. CPU regressions cover
developer roles, typed numeric tool continuation, official output/stream
boundaries, 146 actual-manifest-parser cases with mocked GPU imports and
32 sequential-model weight-policy cases. The benchmark host now selects
embedded speculation for IQuest drafts 2–7, keeps draft1 ordinary and
rejects sidecars/draft8 before loading; all 192 CLI library tests pass.

The actual-weight prefix uses token IDs `[1, 2, 3]` at positions `[0, 1, 2]`
through two layers with Q8 KV and BF16 boundaries. All 21 float stages are
finite/nonzero; embeddings and the three top-8 expert selections/order
match the archived decoded-weight F32 reference. Final hidden mean cosine
is 0.9999563089564 and relative RMSE 0.009561502307, comparable to the
archived native result. Other float stages and source-reference Q8 bytes
differ. Native Q8 activation packing and reduction order differ from
the explicit Torch reference; this is not whole-model quality validation.

## Initial long HTTP reuse: failed

The frozen v4 fixture uses context8192, two continuous banks, chunk128,
partial reuse, embedded MTP draft3/margin0, temperature0, seed1 and
`reasoning_effort=none`. Its 544 inventory-padding lines render to 4371
seed tokens. The warm/restored server uses a 16G disk directory with
minimum cache length1; cold comparison uses reuse off and no disk cache.
Fixture SHA-256 after history construction:
`e1d2aa6c8b6dd17e0985c04e7274b11cffd2316b4cdf19897775cd92ca8fbf38`.

Seed and edited arithmetic replies fail the literal-answer contract:
they start with `4` or `6`, then add an unsolicited request for a clearer
question. The same formatting failure occurs cold. More significantly,
the identical 4414-token append request returns only `5` warm (one
completion token) but `5` plus that extra text cold (23 tokens). Both
finish with `stop`; output and completion count differ. This remains a
real failed reuse comparison, independent of the trace checks below.
The branch request returns `8` in both phases. A restored restart returns
`9` with 4436 cached tokens and matches its cold comparison.

Separately, v4 incorrectly requires `exact`/`fork` labels for append,
branch and restart, rejecting their `partial` labels. The persisted seed
contains 4395 committed tokens, including EOS0 after 23 visible generated
tokens; its retired text key omits that last token. Full rendered-token
comparison rejects the duplicate-EOS candidate and selects token-LCP
reuse. A `partial` label also takes precedence over bank placement, so it
cannot prove or disprove a cross-bank copy. No native bank trace was
captured in this campaign. The v5 runner requires family-matched native
fork evidence; that test correction does not erase the output mismatch
or qualify the initial campaign.

The shorter disabled-thinking v5 campaign also fails its strict answer
contract, including generated prose and repeated `<think>`/`</think>` text.
The pinned official parser passes disabled-thinking text through unchanged;
stripping those tags would conceal a failed output rather than establish
source-protocol parity.

## Bank state and width-dependent numerics

The native diagnostic uses the same 4414-token append request, context8192,
two banks, chunk128 and MTP state enabled. Its checkpoint at 4395 is beyond
the physical 4223-row main ring. Six checks preserve exact payloads:
source preservation, full fork, partial fork, matched-schedule replay,
in-place rewind and disk restore. The full payload is 803,418,156 bytes;
the checkpoint payload is 802,384,480 bytes. Source lineage and memory
fault counts remain unchanged.

Changing the prefill widths changes arithmetic despite exact copies.
In two audited KV layers, rows 0–4351 are bit-exact; the
first changed KV row is 4352, where the final 128-row cold chunk diverges
from the history's prefill/serial schedule. Across rows 4352–4413, K/V
relative RMS differences are 0.001783 and 0.009222 for those layers.
At the final prompt, 159331/160000 logits differ, maximum absolute
difference 6.109375. Both paths choose token532 (`5`). After that same
forced token, the historical schedule chooses EOS0 (24.75 versus token781
24.5); cold chooses token781 (24.75 versus EOS24.25).

The MMVQ and MMQ paths use different Q8 activation scale/sum arithmetic;
the source audit and a separate arithmetic illustration establish that
mechanism, without attributing every whole-model difference to one term.
The measured first-difference boundary and exact same-schedule replays
separate arithmetic sensitivity from bank-copy corruption. They do not
qualify cross-width output quality or erase the long HTTP mismatch.

## Thinking-mode host fixes and reuse

The initial v6 campaign enables `reasoning_effort=high`, preserving the
strict answer forms and full-message cold comparison. It exposes two host
defects: the legacy thinking override changes explicit temperature0 to1,
disabling greedy MTP; retirement drops the reasoning-bearing key, leaving
warm/restored cached tokens at zero. Commit `f94697c5` restricts the legacy
override to other families and preserves IQuest's complete official-Jinja
history. Explicit positive-temperature requests retain ordinary sampling.

The corrected campaign uses context8192, two banks, chunk128, padding64
(530 seed tokens), temperature0, seed1, high reasoning and max_tokens256.
Warm/restored phases use partial reuse, a 16G disk cache and cache minimum1;
cold uses reuse off without disk. With MTP draft3/margin0, seed, warm and
worker restart pass, speculation is active, and native traces prove the
bank fork. Append/edit/fork/restart reuse 564/530/615/668 tokens respectively.
All five warm/cold replies contain the strict expected `4/5/6/8/9`, finish
with `stop` and contain nonempty reasoning. Four entire messages match;
append reasoning wording differs despite the same answer, finish reason
and completion count. The strict full-message cold gate therefore fails.

The matched MTP-off thinking campaign also passes seed, warm and worker
restart, with all five strict answers and stop finishes correct. Three
entire messages match cold; append and fork differ only in reasoning
wording. These results establish bounded reuse/restart functionality and
preserved answers, not deterministic full-message parity. They do not
replace the failed disabled-thinking campaigns.

## HTTP protocols, sampling and concurrency

At context8192/two banks/chunk128 with MTP draft3/margin0, both continuous
and forced-serial lanes pass six buffered/SSE reasoning checks across Chat
Completions, Responses and Anthropic Messages. Each returns `42`, nonempty
reasoning, terminal events and usage; greedy speculation is active. Each
lane also passes Chat/Responses generated-tool continuation with typed
arguments `19,23` and result `42`, plus temperature0.7 high-reasoning
sampling with speculation inactive and zero speculative counter change.

Two actual SSE requests interleave visible generation before either
finishes, reach two in-flight requests, and use the continuous lane. Both
return exact `1..24` sequences and nonempty reasoning. Global fault counts
remain unchanged. Eight continuous disabled-thinking buffered/SSE checks
fail their strict answer-format contract by adding explanations; their
fault counts also remain unchanged. No output criterion was relaxed.
The reproducible API runner is [tests/iquest_http_live.py](../../tests/iquest_http_live.py).

canonical owner, with 2048 raw-prompt tokens, context capacity8192,
chunk128 and 32 EOS-suppressed greedy output tokens. MTP uses draft3,
margin0; ordinary decode uses draft1. Prompt SHA-256 is
`5a321733c27a87b3bb3ce6a6081ebcc8a8653bdccb03944e709da27439df5891`.

| Embedded MTP, draft3 | 60.27–60.28 | 2.08–2.09 | 1.2053–1.2100 |

slower here; it establishes no Agent acceleration. Keep MTP off by default.

## Qualification limits

Start serving with MTP off and thinking enabled; do not force
`reasoning_effort=none`. The checks above establish only their recorded
workloads. Serving qualification fields remain unset because they cannot
express the thinking-mode and prefill-width limitations. Whole-model
source quality and cross-width output parity remain unqualified. This
report establishes no general serving context/bank limit, 512K workload
or acceleration.
