# v0.1.6 — VQ serving, prefix reuse and DGX Spark performance

This release collects the 17 PRs merged after v0.1.5 through #156. It
adds Gemma-4 and Inkling-2 VQ, extends GLM and MiMo serving, and makes
prefix reuse, disk KV, snapshots and banks testable on a supplied model.

The DeepSeek-V4.1-Flash-1017 calibration tools now produce hVQ (#146).
On the released GGUF, hVQ reduced generated-position KL against the
original from 0.2963 to 0.2467 relative to iVQ. Top-1 agreement rose
from 81.87% to 84.02%, while NLL rose from 1.3484 to 1.3603.
[Evaluation and artifact identity](../deepseek41-hvq-evaluation-2026-11-11.md).

## Measured throughput on one DGX Spark

Each row compares the builds named in its linked report across 32 context
lengths from 2K to 64K. Rates are tokens per second, reported as the
median of the run means. DeepSeek used full HTTP prompts. The other
three workloads added 2,048 tokens to a live prefix at each step.

| Artifact and workload | Prefill before → after | Decode before → after | Runs before / after |
|---|---:|---:|---:|
| GLM-5.3 Flash Uncensored mixed IQ2/Q2, raw VMM weight owner, MTP off (#138). [Sweep](../benchmarks/glm53-mixed-spark-64k-2026-11-02/README.md) | 183.2 → 784.7 | 15.09 → 18.92 | 1 / 3 |
| DeepSeek-V4.1-Flash-1017 hVQ, full prompts, automatic MTP (#147–#150). [Sweep](../benchmarks/ds41-hvq-spark-64k-2026-11-12-dense/README.md) | 955.5 → 1,662.2 | 32.38 → 32.52 | 3 / 3 |
| Inkling-2-Small hVQ, resident KV, plain decode (#155). [Sweep](../performance.md#inkling-2-small-vq) | 979.9 → 1,248.1 | 23.41 → 29.79 | 3 / 3 |
| Sage-S2.1-Flash hVQ, two fixed MTP drafts before, up to three after with a 3.0 margin (#156). [Sweep](../glm53-vq-optimization-2026-11-18.md#result) | 1,098.0 → 1,230.3 | 29.94 → 32.51 | 3 / 3 |

Sage prefill improved at all 32 frontiers. Decode improved at 23, tied
at one and fell at eight, including 36.85 → 30.55 tok/s at 32K. In a
separate continuous prefill through 1,040,384 tokens, the final 57,344
tokens ran at 556.61 → 856.73 tok/s. Cumulative prefill took 1,399.1 →
1,032.0 seconds. Sage is the measured representative for the Swift and
Nex card tables. [Long-context curve](../glm53-vq-optimization-2026-11-18.md#long-context-prefill).

## Upgrading from v0.1.5

- Use the pinned Rust 1.100.0 toolchain (#156). The production entry
  points are `ds4`, `ds4-server` and `ds4-bench`. The built-in
  `ds4-agent`, `ds4-agent-c` and `ds4-web` were removed. Connect an
  external agent over HTTP and run its tool loop in the client (#135).
- Replace `--dist-replay-check` with `ds4 --cuda -m MODEL --serving-check`
  on GB10. The Rust hosts now reject the old flag. The new command compares
  declared capabilities with live results. The November 2 checklist passed
  on 19 local artifacts after fixes to prefix reuse and restored state
  (#137). [Checklist and per-model results](../benchmarks/serving-checklist-2026-11-02/README.md).
- The Rust host handles the instance lock, SSD-PLE manifest, sidecar
  binding and stop policy. Qwen, Ling and GLM image preprocessing moved
  to Rust. The JPEG decoder now matches the HF processor, so earlier
  Qwen JPEG disk-KV entries miss once (#136). [Host architecture](../rust-migration/ARCHITECTURE.md).
- For Sage and Swift at 1M with MTP, run `--check-config` on the
  serving host. With about 118.5 GiB available, the automatic planner
  fit one serial session with 2,048 prefill rows and a 4 GiB floor.
  Sage's automatic 4,096-row plan with a 2 GiB floor quoted 117.98 GiB (#156).
  [Memory plans](../glm53-vq-optimization-2026-11-18.md#serving-and-memory).

The [optimization guidelines](../../AGENTS.md#inference-performance-optimization-guidelines)
now take numeric targets from each model's workload (#154).
The linked hardware reports retain their recorded artifact, build and
workload. The GitHub release links the host CI run for the tagged commit.
