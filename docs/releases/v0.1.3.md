# v0.1.3: Qwen-parity serving UX

v0.1.3 is Serving Parity, not kernel cloning. Option names and meanings
are common. Implementation cost, memory, and verification stay per family.
The engine does not treat an impossible or unqualified feature as silently
on. Changing `-m` must not require a new environment-variable dialect.

This ledger is the release plan for P0–P4. The release is complete only
when every phase below is implemented and verified against current
evidence. Dated family reports remain recorded evidence, not a new
hardware campaign.

## Contract

```
CLI / env / verified profile
        ↓
   ServingRequest
        ↓
family + artifact + backend + request kind
        + memory quote
        ↓
   ResolvedPlan  (requested / effective / qualified)
        ↓
Rust policy → native family runtime
```

| Layer | Question |
|---|---|
| Requested | What did the operator ask for? |
| Effective | What did this process actually enable? |
| Qualified | What was verified for this artifact / ctx / bank / modality? |

MTP weights loaded ≠ speculative decode on this request.
Booted at 64K ≠ 64K prompts qualified.

`--print-plan` and `--check-config` show the plan before listen.
`GET /v1/stats` repeats it. Each request records `effective_lane`,
`reuse_kind`, `speculation_active`, and `fallback_reason`.

`--max-seqs` is bank/sequence count, not context. `--ctx` is per-sequence
context. `--mem-floor-gb` is the single floor: Rust admission and the
native planner both read the published `DS4_MEM_FLOOR_GB`. Existing
`DS4_*` names remain aliases.

Reuse, SSD KV, and MTP are separate capabilities. Disk KV is a persistent
checkpoint, not active-bank offload. Three budgets stay distinct: resident
bank / live state, partial-checkpoint memory, disk checkpoint space.
Continuous-bank persistence defaults to 8,192 tokens.

See [serving-contract.md](../serving-contract.md).

## Operator surface

| Area | Name | Rule |
|---|---|---|
| Reuse | `--prefix-reuse off\|exact\|partial\|auto` | `auto` is the best qualified path. Forced `partial` errors if the family cannot do it. |
| SSD KV | `--kv-disk-dir`, `--kv-disk-space-mb`, `--kv-disk-space` | Directory and payload support are checked together. |
| MTP | `--mtp`, `--mtp-draft`, `--mtp-mode off\|auto\|on` | Sidecar, activation, and draft length are separate. `on` does not ignore unsupported sampler/lane/artifact mixes. |
| Prefill | `--prefill-chunk`, `--prefill-chunk-live` | Scheduler yield vs native workspace capacity. |
| Concurrency | `--max-seqs N\|auto` | `--cont-width` and `DS4_SERVER_COALESCE_MAX` are aliases. |
| Floor | `--mem-floor-gb` | One value, published to native and Rust. |
| Inspect | `--print-plan`, `--check-config` | Features, artifact, expected memory, fallbacks. |

## Reuse situations (P1)

| Situation | Required ability |
|---|---|
| Same chat, append | Prefill only the suffix at the current frontier |
| Edit or branch | Restore a valid checkpoint at or below LCP, replay the gap |
| Other bank, same prefix | Fork/copy that preserves the source |
| Restart, continue | Restore a disk payload and match the *rendered* follow-up prefix |

Save/load success is not a Chat cache hit. Step's official template drops
prior empty thinking blocks, so a stored prompt can miss the re-rendered
one. Matching that text is not enough either: the stored KV still holds
the dropped block, so a hit needs a checkpoint captured at the history
frontier, not a text-identity restore over a different token sequence.
Cache identity includes weights/quant, state layout, RoPE, the token
prefix, and media identity. Template/tokenizer changes invalidate or
declare compatibility. MTP-in-checkpoint compatibility is separate.

Host policy owns checkpoint selection, memory budget, eviction, and
hit/miss reasons. The native family owns snapshot/restore/fork/truncate
accuracy. Missing checkpoints replay, and the miss reason is visible.

### P1 status

Landed: `reuse_miss` carries the four miss reasons from the decision that
produced them, on both lanes, and `GET /v1/stats` reports it beside
`reuse_kind`. Append, edit and restart are read back over the HTTP door.

Open, each for a stated reason:

- **Step restart hit.** Rendered-text identity is not token identity, so
  the P0 attempt was reverted: the official follow-up render drops the
  empty `<think>` pair the stored KV still holds. The sound form is a
  checkpoint at the *history frontier* — the position before the
  generation-only suffix — because that prefix is a token prefix of the
  next render. `Session::sync_progress` already reports mid-prefill
  positions. It changes a KV path, so it lands with a GB10 proof.
- **Fork over HTTP.** Fork happens inside the native bank admission; the
  model-free door cannot reach it. Covered by admission unit tests until a
  GPU host runs the lane.
- **EXAONE partial reuse.** `ds4.c` leaves `supports_partial_reuse` false
  for the EXAONE batch runtime because it has no `checkpoint_slab`; every
  other family builds one with a family-specific capture layout. Native
  work, and the plan already refuses to claim it (`partial_runtime`).
- **Qwen / Solar / Motif regression.** Live runs on the reference host.
- **Bank-budget refusals have no reason.** When a checkpoint this request
  could have used exists but no bank can host the restore, the bank lane
  reports no reason rather than an absence it would be wrong about. The
  contract's reasons describe the cache, not the bank budget. A payload
  that cannot be read is not this case: it reports the mismatch.

EXAONE is the first partial-reuse expansion. It may use Step's sliding-
window *shape*, not LLLG-as-SWA.

## Resource policy (P2)

Scheduler chunk (how often control returns) and native chunk capacity
(kernel/scratch/graph max) stay separate. Adaptation picks from a
verified discrete set. Do not `setenv` a global chunk at runtime past
the allocated capacity.

`max-seqs=auto` quotes shared weights, per-bank target and MTP state,
scratch/graphs, partial-checkpoint pool, PLE, serial media reserve, and
host floor. Two text banks that 503 every image request are not a
mixed-modal default.

### P2 status

Landed: yield snaps to `VERIFIED_PREFILL_CHUNKS` under the fence, stays
apart from `native_chunk`, and env publish never exceeds native capacity.
An explicit yield past native is `chunk_past_native` and refuses listen.
`attach_host_quote` fills the named budgets from the GGUF span and live
host memory on `--check-config` and on the post-fit plan; a mix that
cannot host even one bank is `quote_overflow`. A media-serial family's
auto default is one bank unless a serial-media reserve is quoted.

Open: live overlap of a long prefill with a concurrent decode on GB10,
recorded beside the unit tick that already steps decode during a peer
prefill.

## MTP (P2/P4)

Three layers: family can run MTP; weights/state are ready; this request
uses speculative decode. `--mtp` alone does not mean every request
speculates. Step sampled requests keep predictor state and use ordinary
decode.

Primary metric is net decode speed: committed output tokens / (draft +
verify + commit/rollback time). Acceptance rate is not the objective.
Qwen draft/prefix wins stay family-local until state dependencies allow
the same skip.

## Optimization tracks (P4)

Track A (serving UX): warm append, partial fork, restart hit, queue wait,
prefill-vs-decode delay, media fallback. Judge HTTP TTFT and end-to-end
request time. Benchmark `first_token_sec` after prefill is not request
TTFT.

Track B (family kernels): unexpected fallback → host/I/O wait → repeated
quantize/convert → routing/launch fragmentation → shape fast path →
dominant kernel. Evaluate removed waste on that family's bottleneck.

Shared serving benchmarks: KV-cold prefill, warm append, partial branch,
restart restore, decode-vs-long-prefill, MTP/media/tool mix. Do not
average short with long, text with media, or greedy with sampling.
Record 300–2200 MHz limits and observed clock/temperature. NCU clock
overrides are not speed evidence.

## Family status at plan time (main@a1700d2)

These are implementation and verification ranges, not theoretical
limits. MTP without weights is a model contract. Missing snapshots,
serial-only live serving, and a current graph cap are work items.

|---|---|---|

| K-EXAONE | Persistent multi-bank, disk KV, exact-frontier reuse | Partial checkpoint/fork |
| K2-Horizon | 32K one-bank; disk KV and external owner unverified; no MTP contract | State save/reuse qualification. Do not invent MTP. |
| dots3 | Live serial; snapshot path; MTP bound, not executed | Bank, partial, MTP execution as separate tasks |

| DeepSeek | Continuous/serial, compressed disk KV, MTP/DSpark | Express existing features in this contract; regress |
