# v0.1.1: measured performance workflow and FP8 PLE

The measured performance workflow is qualified on the GB10 reference host.
The release adds Rust performance orchestration and optional official Qwen FP8
PLE sidecars. The performance workflow keeps the inference ABI and official
optional NVTX annotations intact; FP8 support changes native PLE loading,
gathering and KV format identity.

## Scope

- `inspect --calibrate`: device identity/resource limits and checked CUDA copy,
  FP32 SIMT FMA, and host-launch measurements.
- `scout --fit --ncu`: fresh unprofiled measurements, Nsight phase attribution,
  resource bounds and bounded application-replay counters.
- `scout --collector cupti`: real CUDA activity/NVTX collection through the
  separate optional CUDA 13.3 helper.
- `compare --regression`: matched workload and repeated full-vocabulary/greedy
  proofs, separate prefill/decode/first-token metrics, conservative verdicts.
- `optimize --auto`: explicit runtime experiments, bracketing controls,
  correctness checks, rejection reasons and retained raw evidence.
- `DS4_QWEN_PLE_DIR`: optional official FP8 PLE for existing Qwen main GGUFs,
  bounded compressed-page storage, BF16 gather output and separate KV tags.

See [commands and evidence contracts](../ds4-perf.md). The control executable
builds without CUDA. No CUDA/CUPTI profiling dependency enters `ds4-core`,
`ds4-sys`, the native bridge, or ordinary inference builds.

## FP8 PLE qualification

[PR #22](https://github.com/Baekpica/ds4-dfm-rs/pull/22) adds the selected
sidecar to loader, CUDA gather, snapshot identity and performance evidence.
The [FP8 guide](../qwen38-ple-fp8.md) records the exact artifacts, commands,
12 paired CSVs and compatibility receipts. Measurements use `84d183c`;
final live compatibility checks use `2b7aee7`.

- Both FP8 Q5 main models pass two-bank/MTP/KV/fork/lifecycle checks, direct
  65,536-token prefill with finite full-vocabulary logits, and short Rust HTTP
  text/concurrency/tool-KV/image checks at 262,144 configured context.
- Uncensored FP8 restores 1,233 disk-KV tokens after a cold process restart.
  Base Q6 has a separate 2K inference/logit smoke, without new serving scope.
- The original warm-session 2K–64K card sweeps report base/Uncensored prefill
  +6.3%/+5.1% and decode +1.2%/+0.1%. These are medians of three run means per
  format/model, with fixed 2 GiB PLE cache, 16 workers and MTP draft 2. One
  base BF16 run autoquenched MTP; every run is retained. FP8 can change tokens
  and MTP acceptance, so these are not isolated arithmetic speedups.
- PLE physical files shrink by 50%; source-compatible FP8 decoding does not
  establish BF16-equivalent task quality or long-context retrieval accuracy.
- Base BF16 passes the lifecycle gate. Uncensored BF16 has a partial-fork
  token mismatch (553 versus cold oracle 8), reproduced by pre-PR `0290c4f`.
  This existing artifact-specific failure remains an explicit limitation.

The merged implementation at `923cdd8` passes
[host-parity CI](https://github.com/Baekpica/ds4-dfm-rs/actions/runs/34199780753),
including serialized workspace tests, PLE format tests, formatting, Clippy
and all host targets. These CPU checks do not replace the scoped GPU receipts.

## Observed workflow failures and corrections

Default NCU kernel replay attempted to back up accessible model memory and
triggered the host memory guard. Both task-owned scopes stopped; memory was
recovered before retrying. The failed report and memory samples remain in
`qwen-nsys-release/` and `nsys-release.memory.jsonl`.

The corrected capture uses application replay with strict matching of kernel,
grid/block, context and stream. A real prefill-kernel capture completed eight
passes without memory pressure (`ncu-app-smoke/`). NVIDIA describes the memory
and determinism tradeoff in its
[application replay documentation](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html#application-replay).
NCU's details CSV page with base units matches the normalized metric contract;
a fixture from this capture covers the actual export.

The first bracketed campaign (`qwen-auto-final/`) also exposed JSON floating-point
drift when automatic comparison reloaded its own exact sample summaries. Both
controls and the candidate completed, with zero logit/token mismatches, but the
trial recorded a comparison-load failure. Enabling serde_json's `float_roundtrip`
feature fixes the parser without weakening summary validation. A captured real
comparison fails before that change and passes afterward; altered summaries
still fail. The original failed decision remains intact.

## Limits

Calibration establishes an observed copy/FP32/launch envelope, not tensor-core
peak throughput. Fit reports resource upper bounds, not measured occupancy or
inferred operand dimensions. NCU samples the first matching launch of each
phase's top aggregate kernel. Missing hardware counters remain unknown.
CUPTI phase attribution uses GPU execution inside the Rust NVTX time window;
it does not claim CUDA API correlation attribution. GPU process checks are
endpoint snapshots and cannot detect transient contention between snapshots.

Candidate selection is rule-based hypothesis generation. The PLE-worker
experiment was triggered by prefill kernel coverage of 73.6% and a largest
observed gap of 169.7 ms. Qwen's existing worker control supplies the experiment;
doubling 16 workers to 32 is not a calculated optimum or proof of a PLE stall.
Calibration and NCU provide additional evidence but did not establish that cause.
Full input hashing is outside inference timing and took most of the roughly
40-minute one-candidate campaign on this host.

The short Qwen performance workflow validates orchestration. Its production
service restoration receipt uses the existing v0.1.0 binary and 262,144-token,
two-bank configuration; it is not an FP8 or full-context prefill measurement.
FP8 qualification is limited to the separate checks above. Other model-family,
long-context and CUDA capture/eager claims retain the scope in the
[v0.1.0 ledger](v0.1.0.md); no FP8 256K/512K prefill or broad quality gate is
claimed.
