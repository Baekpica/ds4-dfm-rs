# v0.1.2: official chat templates and Inkling

This checkpoint includes [Inkling Small / MTP integration](../inkling-small.md)
and a shared input-template path for supported artifacts. Rust executes the
official model Jinja through a local `hf-chat-template` adapter. Tensor loading,
tokenization, media processors and output protocols retain their own contracts.
The Jinja change does not modify CUDA/MMQ/VMM numerical kernels.

## Changes

- Load `chat_template.jinja` beside GGUFs, then local tokenizer configuration,
  then embedded GGUF metadata. Compile once; no runtime HF downloads.
- Normalize all three chat APIs, tools, reasoning and media content. Use the
  same template path for one-shot CLI and structured REPL history.
- Restore Messages/Responses tool-only requests from live structured history.
  Validate complete token prefixes before serial/continuous KV reuse; refill
  rewritten prefixes.
- Re-render the valid conversation for malformed-tool correction retries.
- Recognize GLM's official user/observation stop tokens, which previously leaked
  into a real CLI answer after `4`.

See [input/output boundaries and asset setup](../chat-templates.md), the
[official fixture provenance](../../tests/fixtures/chat-template/README.md),
and the [dependency pin/compatibility patches](../../vendor/hf-chat-template/VENDOR.md).
The built-in coding executor remains DeepSeek DSML; other families use HTTP
tool clients. DeepSeek V4 provides a Python encoder rather than official Jinja
and remains an explicit encoder exception.

## Reproducing bounded API checks

Start a guarded, ready server for the selected artifact. Then run:

```sh
python3 tests/chat_template_live.py \
  --url http://127.0.0.1:18085 --model MODEL_ID \
  --output scratch/jinja/http-MODEL_ID
```

The fixture checks simple multi-turn text and buffered/SSE tools across Chat,
Messages and Responses. Chat replays full history; Messages/Responses also
check tool-only replies with omitted schemas.
For an image-capable server, add
`--images tests/fixtures/chat-template/images` to check red/blue input on all
three APIs. Model loading and memory ownership are managed separately.
Inkling's recorded image run also uses `--image-order text-first`. Use
`--concurrent` only with two banks and a supported streaming tool lane.
The K2 thinking run uses `--reasoning-effort high --max-tokens 512`.

## Limits

These are short input/protocol checks. They do not renew long-context,
capture/eager, numerical parity, quality, performance or sustained concurrency
claims. Earlier native qualification retains the exact scope in the
[v0.1.0](v0.1.0.md), [v0.1.1](v0.1.1.md) and
[Inkling](../inkling-small.md) ledgers. Jinja support alone does not provide
new modalities, codecs, tensor layouts, output grammars or execution lanes.
