# K2 and GLM qualification gates

These commands prepare P3 evidence; their presence does not qualify a family.
Use the same checkout, executable and artifact for every phase. Preserve the
300–2200 MHz clock limits, record observed clocks, and run one model at a time.
The HTTP scripts never start or stop servers.

## Artifact identity

Record the checkout SHA and diff, executable SHA-256, all shard paths, sizes and
SHA-256 values, tokenizer/template provenance, launch argv/environment, and
driver/CUDA versions. K2's local `MQ87-SHA256SUMS` supplies the expected shard
hashes; record whether they were independently verified. Save that information
as `artifacts.json`. A path or quantization label alone is insufficient.

## K2

The [2026-09-17 native receipt](../benchmarks/serving-v013-2026-09-17/k2.json)
records the fixed 1024-context lifecycle gate. K2 now matches the host's
exact-only policy: exact extensions keep the live prefix, while edited or
truncated prompts replay from zero. The edited fixture has identical full
logits and all 16 greedy tokens to its cold control. Exact append still reports
cross-prefill-width logit drift with all 16 tokens equal; this short fixture
does not establish broader numerical or quality parity.

The integrated5 32K one-bank HTTP attempt stopped before listen: all weights
were resident (96.41 GiB), but the unchanged 8 GiB host guard tripped at
7.682 GiB available during bank allocation. K2 allocates its full-attention KV
eagerly, including 7.625 GiB for the 32K bank. The preflight predicted 8.189 GiB
remaining; this was not a complete peak-memory estimate. Cleanup succeeded,
and no HTTP generation, restart reuse or cold comparison ran in that attempt.
It does not extend the historical 32K serving qualification to the current
host state.

Subsequent integrated6 attempts retained the 32K context and one bank:

- With the user-authorized external 4 GiB floor, native admission refused
  the derived 6 GiB fit headroom (4 GiB floor plus 2 GiB boot burst).
- Pinning native fit headroom to 4,096 MiB passed that admission, but the
  unchanged PSI20 guard stopped startup at 7.086 GiB available / PSI 21.79.
- The separately authorized task-local PSI30 guard then allowed both seed
  and restored processes to boot. It retained the 4 GiB hard floor, 4 GiB
  fit headroom, requested cgroup max/high of 104/100 GiB and 12 GiB reserve;
  the shared guard was unchanged. PSI30 applies below 8 GiB available.

The PSI30 lifecycle failed on the first restored request: it reported cold
reuse with zero of 545 prompt tokens cached. Seed and restored requests each
returned one token with `finish_reason: "length"`; that equality is not an
answer-quality check. Append, branch, edit and fresh cold controls did not run.
The minimum sampled host availability was 4.985 GiB, no memory/PSI trip
occurred, and both owned scopes were drained with no cleanup errors. The
miss remains under investigation, and 32K HTTP disk reuse stays unqualified.
The receipt appends this failed result and all three prior failures without
replacing the native proof or historical 8 GiB attempt.

Build after the central CUDA build, then run the model gate while no other
model owns GPU weights:

```sh
make -j1 tests/test_k2_lifecycle
./tests/test_k2_lifecycle "$K2" 1024 > scratch/k2-native.log 2>&1
```

The model-free rewind policy regression is `make tests/test_k2_rewind &&
./tests/test_k2_rewind`; its K2 span is zero at contexts 1024 and 32768, while
K-EXAONE's resident LLLG span is unchanged. The corresponding host check is
`cargo test -p ds4-core --lib --locked k2_sync_extends_or_rebuilds`.

This gate covers full-vocabulary bit identity immediately after serial disk
restore, corrupt-payload invalidation, append/edit against 16-token cold greedy
controls, exact bank fork without changing its source, and bank save/restore
across context recreation. It prints full-vocabulary suffix drift for review;
unexplained drift remains an open numerical gate even if greedy tokens match.
The two-bank fork uses a short context and does not qualify two-bank 32K serving.

Use in-process VMM for the HTTP gate. External weight-owner import remains a
separate unqualified path. Start a managed worker with an empty cache directory:

```sh
DS4_SERVER_PERSIST_MIN_TOKENS=1 "$SERVER" --cuda -m "$K2" \
  --host 127.0.0.1 --port 18038 --model-id k2-horizon --ctx 32768 \
  --max-seqs 1 --mtp-mode off --prefix-reuse exact \
  --kv-disk-dir "$PWD/scratch/k2-kv" --kv-disk-space-mb 4096 \
  --kv-cache-min-tokens 1
```

Unset inherited IPC manifests before this launch. The short fixture needs the
explicit persistence minimum; production's 8192-token bank minimum is unchanged.
With the actual worker PID, run:

```sh
python3 tests/k2_lifecycle_live.py seed --pid "$WORKER_PID" \
  --output scratch/k2-http --artifact-manifest scratch/artifacts.json
```

Restart that worker with the identical command and cache, then run `restored`
with its new PID. It checks exact restart reuse, appended suffix reuse, a second
branch from the saved parent, and cold fallback after an early edit. HTTP
one-bank branch reuse is distinct from the native two-bank copy gate.

For `cold`, start a third fresh worker with the same model/context/bank/MTP
settings, `--prefix-reuse off`, and no disk arguments. The script checks all four
requests against the restored run's output and completion count, with zero cached
tokens. Binary, artifact-manifest and process identities are checked across phases.
All phases retain requests, responses, usage, timing and `/v1/stats` traces.

## GLM

```sh
make -j1 tests/test_glm53_bounds tests/test_glm53_session
./tests/test_glm53_bounds
cargo test -p ds4-core --lib --locked serving::tests -- --test-threads=1
python3 tests/glm53_bounds_live.py config --server "$SERVER" --model "$GLM" \
  --output scratch/glm-bounds
./tests/test_glm53_session "$GLM" > scratch/glm-native.log 2>&1
```

The model-free native gate performs no GPU initialization. It checks lazy
admission at 2048, rejection at 2049 even with memory-fit checks disabled,
invalid contexts/backends/sidecars, and the explicit unsupported snapshot path.
The metadata-only configuration gate requires an idle host for honest memory
admission. The model-backed session allocates context 2048, rejects 2049, and
checks finite logits for a two-token prefill/decode smoke; it does not evaluate
a full 2048-token prompt.

Start a managed serial GLM worker, without disk or MTP:

```sh
"$SERVER" --cuda -m "$GLM" --host 127.0.0.1 --port 18039 \
  --model-id glm-5.3-flash --ctx 2048 --max-seqs 1 \
  --prefix-reuse off --mtp-mode off
python3 tests/glm53_bounds_live.py http --model "$GLM" --pid "$WORKER_PID" \
  --output scratch/glm-bounds
```

This checks short serial generation and explicit refusal of an over-cap prompt.
Snapshots remain unsupported. A larger context requires an implemented compact
indexer/cache path and its own numerical and lifecycle evidence.

Model-free request-fixture regression:
