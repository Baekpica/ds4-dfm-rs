# Ling-3.0-flash-VL YaRN 256K and 8K opt, 2026-09-16

YaRN factor 2 on the official 131,072 rotary window, plus the 8K
prefill/decode rounds that shipped with it. One GB10, the MQ-Q5 language
shards and BF16 mmproj, `ds4-bench --chat-prompt-file
speed-bench/promessi_sposi.txt`. CSVs live under
`scratch/ling-yarn-opt/`.

## YaRN

`-c 131072` and below keep the factor-1 M-RoPE table. `-c 262144` builds
the Transformers YaRN table (`rope_type=yarn`, factor 2, `rope_theta=6e6`,
beta 32/1, `original_max_position_embeddings=131072`) and scales sin/cos
by `0.1*log(2)+1`. `partial_rotary_factor=0.5` is already the 64-dim
rotary tail. The host refuses `262145`.

## 8,192-token bench

Greedy 8 decode tokens. Fresh process each row. Prefill chunk stayed 2048.
The 8K A/B rows did not sample clocks. A later proof window on the same
GB10, same day, stayed at **SM 2190–2197 MHz** (user range 300–2200;
`nvidia-smi --query-gpu=clocks.current.sm`).

| round | change | prefill tok/s | decode tok/s | decode ss | keep |
|---|---|---:|---:|---:|---|
| r0 | baseline | 1131.19 | 15.90 | 19.95 | — |
| r1 | `DS4_LING3VL_PREFILL_CHUNK=4096` | 1076.01 | 15.47 | 19.93 | no |
| r2 | KDA decode BF16 pair | 1133.90 | 17.79 | 23.06 | yes |
| r3 | MLA decode BF16 pair | 1134.87 | 17.94 | 23.23 | yes |
| r4 | KDA prefill one-shot F32→BF16 | 1146.84 | 17.76 | 23.18 | yes |
| r5 | same convert on MLA/FFN | 1148.88 | 17.71 | 23.26 | no |

Adopted vs r0: prefill **1131 → 1147 tok/s** (+1.4%), decode **15.90 → 17.8
tok/s** (+12%). r1 doubled the workspace and lost. r5 did not beat r4.

This is a `ds4-bench` 8,192-token raw prompt, not the earlier HTTP 1,072-token
qualification (1,461 / 19.8). They are different workloads.

## Correctness proof

`tests/ds4_proof.py --scenario ling3vl-opt-parity` (smoke, 64 greedy tokens,
builtin prompt 1, `--nothink`). Same binary, kill switches off vs on.

| Path | Kill switch | Token IDs vs default |
|---|---|---|
| KDA prefill convert-once | `DS4_LING3VL_NO_BF16_REUSE=1` | identical (64/64) |
| KDA/MLA decode BF16 pair | `DS4_CUDA_NO_BF16_ROWS_PAIR=1` | first flip at step 8 |
| both | both | same flip as pair-only |

Step 0 logit matched. The flip is `for` (22.567) vs `that` (22.638). Both
continuations stay the same speculative-decoding explanation. That is the
mixed-quant BF16 pair-vs-two-plains contract, not a KV or position bug.
`DS4_CUDA_NO_BF16_ROWS_PAIR=1` restores token identity. Report:
`scratch/ling-yarn-opt/ling3vl-opt-parity.json`.

## 262,144-token session smoke

`--ctx-alloc 262144 --ctx-start 256 --ctx-max 256 --gen-tokens 2` allocated
`Ling graph ctx=262144` (KV 1.97 GiB, workspace 1.24 GiB) and decoded two
tokens. That proves the YaRN session path. It is not a 256K-prompt
throughput number.
