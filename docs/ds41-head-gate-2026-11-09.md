# DS4.1 coarse-to-fine head gate (2026-11-09)

Question: can a 1024-column Q8 sketch of `output.weight` pluck the true
argmax into a 2048-row candidate set, on this artifact and our own hidden
states? If yes, the head read drops from 372.3 MB to the sketch plus a small
exact rescore, the last measured decode lever in the 3-5% band.

Reference: `/data/Flash1017-Engine` at `c65fe96`,
`crates/flash-core/src/flash1017.rs` — `build_and_save` :3670-3760 (column
leverage `col_rms*|final_norm|`, half top-energy + half stride, per-row
symmetric Q8 sketch) and `predict_coarse_to_fine` :3850-3990 (1024-col
matvec, `k` clamped to `[512, vocab]`, `core_anchor_count = min(512, k/2)`,
candidates = the first 512 vocab ids plus the top `k - anchor` sketch rows
among ids >= 512, then exact rescore). The only intended deviation: the
reference rescores BF16 rows; this artifact's head is Q4_K, so the rescore
dequantizes the artifact's own rows. That is the arithmetic the engine
already serves.

## Method

1. Engine dump. `DS41_GEN_HIDDEN=<path>` was added beside the kept
   `DS41_GEN_LOGITS` dump (`ds4_ds41_draft.inc`): one E-float row of the
   pre-head normed state `xn` per emitted position, written in the same
   order and count as the logits row. Row index is the forward's own
   `n - 1`, the same row the head consumed (`head_last_only` copies
   `xn[n-1]` to `xlast`, so `last_logit_row = 0` is not the source row).
2. Two measurement windows on the Spark, MTP off (`--mtp-mode off`,
   `tok_per_step 1.00`), one greedy request each, binary
   `0d1a35ccb715c4ea9fe172197998c03ec0c1497d6e5e57b413a69530a395af52`
   (`make ds4-server CUDA_ARCH=sm_121`). The pre-stager server
   (`139aef25...`) was restored after each window.
3. Gate harness `misc/scratch/ds41_head_gate.rs` (scratch, gitignored):
   reads the raw `output.weight` q4_K bytes and `output_norm.weight` f32
   copied from the GGUF, rebuilds the reference sketch, then for each
   position scores the 1024-column Q8 matvec, picks candidates, and
   rescores with the artifact's q4_K rows.

Artifact tensors (GGUF header): `output.weight` q4_K `[5120,129280]`,
372,326,400 B at abs 113,183,795,072; `output_norm.weight` f32 5120 at
abs 113,183,774,592. Q4_K dequant mirrors `cuda/ds41_q4k.cuh`
(`v41_q4k_sm` / `v41_q4k_blk_acc_reg`) and the golden
`src/common/ds4_quantfmt.c` decoder it cites.

## Results

Two windows, both greedy, clocks 2463 MHz:

| window | prefill | decode | positions |
|---|---|---|---|
| 2048 ctx | 966.9 tok/s | 30.0 tok/s | 256 |
| 8192 ctx | 1083.6 tok/s | 30.0 tok/s | 512 |

Candidate recall (the engine's own full-head argmax landing in the set) and
top-1 of the exact rescore:

| positions | k=1024 | k=2048 | k=4096 | top-1 @2048 | top-1 @4096 |
|---|---|---|---|---|---|
| 2048 ctx, 256 | 256/256 | 256/256 | 256/256 | 256/256 | 256/256 |
| 8192 ctx, 512 | 498/512 | 508/512 | 512/512 | 508/512 | 512/512 |

At 8K the 2048 set misses 4 positions (5, 334, 369, 372): 0.78%. The 4096
set captures all 512, and where the true token is present the exact rescore
ranks it first in every position (p50/p90/p99/max rank 0). 173 of the 256
2K positions and the corresponding majority of the 8K positions are ids
>= 512, so the recall is not the 512 anchors doing the work.

## Reading

- The 2048-candidate set is not safe at 8K: four positions would emit a
  token the full head would not choose. The 4096 set is clean on both
  samples and still removes most of the head stream: 132.4 MB sketch
  (129,280 x 1024 Q8 + 517 KB scales) + 4096 x 2880 B = 11.8 MB rescore
  = 144.2 MB per head call against 372.3 MB, 2.58x less.
- The head is read twice per MTP step (verify and draft). At 372.3 MB each,
  744.6 MB of the ~6.8 GB step; at 144.2 MB each, 288.4 MB. The saved
  456 MB is ~6.7% of step bytes at the measured 187 GB/s, i.e. ~2.4-3.5%
  decode once launch and rescore overhead are paid. That stays inside the
  3-5% ceiling, at the bottom half of it.
- Sampled requests cannot use a truncated head as it stands. The engine's
  device sampler and the sampled-speculation verify draw from the full
  logits row; a 4096-logit head changes the top-p/top-k support and the
  sampling distribution. A two-stage head is therefore greedy-only unless
  the sampler is rebuilt on a coarse-to-fine tail; this is a contract
  constraint, not an implementation detail.
- The sketch is a derived artifact (132.9 MB) built from `output.weight`.
  It can be built at boot (read 372 MB, quantize, ~1-2 s) or shipped as a
  sidecar. It is not an artifact recipe change: the GGUF stays as it is.

## Verdict

Gate passes at k=4096 on 768 positions across 2K and 8K contexts: 100%
candidate recall and 100% top-1 agreement, with the true row ranked first
in every rescore. k=2048 fails 4 of 512 at 8K and is not adopted. The
implementation is a greedy-path head replacement; sampled requests keep the
full head until a coarse-to-fine sampler exists. Next unit, not this one:
build the sketch loader plus coarse matvec, device top-4096 and exact
q4_K rescore, then gate speed and teacher-forced NLL/top-1 on the served
model.
