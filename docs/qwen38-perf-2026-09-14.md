# Qwen performance, 2026-09-14

This campaign references [qwen3.8-Flash-DGX](https://github.com/blazux/qwen3.8-Flash-DGX/tree/d542745cd41045bcd71b9d7dbe659bca014202bf).
Results are scoped to the explicitly named Base or Uncensored Q5 artifact
and workload. They do not replace the older card sweep.

## Protocol

- Baseline code: `c40d3753d225e59b821834c6d948656841fedf47`.
- DGX Spark GB10, CUDA 13.3, `sm_121a`; user-managed 300–2200 MHz range.
  Graphics-clock medians were 2190 MHz in all speed pairs.
- Base `MQ-Q5-SSD-PLE-BF16` weights with the FP8 E4M3FN PLE sidecar,
  2 GiB PLE cache, 16 workers, 8192 prefill cap, MTP draft 2.
  One resident VMM owner; each measurement used a fresh guarded worker.
- Exact `speed-bench/promessi_sposi.txt` fixture, SHA-256
  `f53e0d80cb2d4492d24ebd63c7000c397b16ae70f9bf09b3763e5d8323ec209f`.
  Independent 8192/65536 frontiers, 128 generated tokens, three alternating
  A/B pairs per frontier. Benchmark generation excludes EOS, as before.
- Adoption threshold: >=2% end-to-end gain without a repeatable >2% loss
  in another principal metric. Profiled timings are diagnostic only.

## MTP output vocabulary

The draft scores the first 65536 BPE IDs, non-normal token types and IDs
observed by its shifted input stream. The target output and verification
remain full vocabulary. No weight conversion or extra model file is needed.
The list occupies at most one vocabulary-sized GPU ID array, a host ID array
and a byte membership map per graph. It resets with the graph and whenever
bank copy or checkpoint restore replaces its history; it is a proposal hint,
separate from accepted KV state. A restore can change proposals.

GPU argmax alone was rejected: 8K decode medians were 27.87 versus
28.00 tok/s (+0.47%), below the threshold. Its compact-result helper is used
by the separately measured vocabulary reduction.

All rates below are tok/s. A uses the full head and CPU selection; B uses
the compact head and GPU selection.

## QSA Tensor Core experiment: rejected

Two prefill-only BF16 QK/PV implementations retained FP32 cache storage,
softmax and output accumulation. Both passed an independent rounded-input
attention reference (max error about 5.6e-7), masked/tail cases and the
unchanged FP32/decode checks.

| 8K candidate | Prefill tok/s |
|---|---:|
| Existing FP32 fused QSA | 1418.32 |
| 64-slot tiles, 128 threads | 725.83 |
| Padded 32-slot tiles, 256 threads, reused scratch | 1224.59 |
| Fresh FP32 control after both experiments | 1423.31 |

The first kernel had only four active warps/SM and about 69% excessive
shared-memory wavefronts. Reusing QK/PV scratch and padding the shared tiles
reduced that cost, but the second implementation still regressed prefill
about 14%. These obvious regressions were stopped before an adoption sweep.

Full-model 8K prefill logits changed: max absolute error 1.02–1.16,
RMS 0.175–0.201; the frontier argmax stayed the same, while generated tokens
first differed at offsets 41/39. Kernel-reference agreement alone therefore
was not a full-model parity claim. No broad quality qualification is claimed
for these discarded candidates. The production QSA implementation is intact.

Both patches and diagnostics remain in the local campaign directory as
`qsa-tc-v1.patch`, `qsa-tc-v2.patch` and `qsa-tc-*.ncu-rep`.
The initial NCU run used default clock control and reported 2.42 GHz; it is
not speed evidence. Subsequent NCU runs explicitly use `--clock-control none`.
The unprofiled A/B graphics-clock medians remained 2190 MHz.

## MTP prefix cache preparation

An MTP prefix consumes shifted target hidden states. Its attention output
and MoE result are discarded: only QSA raw/pooled index history and K/V
are carried forward. The new path skips query projection, query normalization
and RoPE, selection, attention output, output projection and subsequent HC/MoE
when no draft logits are requested. Real draft generation keeps the full layer.
The private QSA pass selector leaves target and two-bank QSA in full mode.
`DS4_QWEN_MTP_FULL_PREFIX=1` restores the original prefix computation.

A uses the adopted compact vocabulary plus full prefix computation; B adds
cache-only prefix preparation. All rates are tok/s.

| Context | Pair | Prefill A | Prefill B | Decode A | Decode B |
|---|---|---:|---:|---:|---:|
| 8K | 1 | 1421.26 | 1431.79 | 28.52 | 28.73 |
| 8K | 2 | 1421.65 | 1434.74 | 28.71 | 28.76 |
| 8K | 3 | 1423.22 | 1434.50 | 28.49 | 28.85 |
| 64K | 1 | 1517.24 | 1555.05 | 29.67 | 29.64 |
| 64K | 2 | 1516.44 | 1556.69 | 29.44 | 29.68 |
| 64K | 3 | 1513.92 | 1554.10 | 29.58 | 29.66 |

Median prefill gains are **0.90% at 8K and 2.55% at 64K**; decode changes
are +0.84% and +0.27%. Every pair matched all frontier logits and all 128
generated IDs exactly. Draft acceptance was unchanged, no quench occurred,
and graphics-clock medians remained 2190 MHz.

The benchmark's `first_token_sec` measures the first decode step after
prefill, not request TTFT. Its medians increased from 44.0 to 46.3 ms at
8K and 45.4 to 47.6 ms at 64K. HTTP TTFT is qualified separately.

The native verify gate compares 400 live MTP prefix rows against the full
path: K/V, raw/pooled index, length and pending target hidden state match
exactly. The subsequent 48 target verify steps (32 hits, 16 misses) have
zero logit/state mismatches. Two-bank, disk-KV, partial-fork and graph
lifecycle gates also pass.

A diagnostic 6143-row MTP prefix trace shrank from 78 kernels / 136.47 ms
of GPU time to 27 kernels / 21.99 ms. This local reduction is not the
end-to-end gain reported above.

Three fresh HTTP pairs produced identical outputs for all five text cases.
TTFT median changes were -1.73% (Korean extraction), -0.94% (code), +0.44%
(tool JSON), -2.34% (time arithmetic) and -0.93% (English scheduling).
Total request times fell 0.42–2.60%. The same time-arithmetic and strict-JSON
baseline failures described above remain; no new failure appeared.

## Combined Base serving checks and limits

Fresh controls disabled all three diagnostic optimizations; candidates used
both adopted paths. Both used 262144 configured context, two banks, the
original serving options and separate empty 32 GiB disk-KV directories.

- The six fixed image cases (256–1920 pixel inputs, screenshot, invoice,
  photograph and four-image request) returned identical outputs, with zero
  cached prompt tokens. Four descriptions reached the shared 96-token cap.
  Separate focused checks correctly returned invoice total `$385.00`, both
  dashboard Failed counts `3`, and photo subject Earth.
- A changed screenshot returned `9` with zero cache reuse; its unchanged
  predecessor returned `3`, and a text follow-up reused 794 tokens and
  answered `Failed`. Text continuation reused 1463 tokens in both variants.
- Both concurrent requests completed the full 1–40 sequence. A required
  `inventory` tool call returned identical arguments; replaying stock 19
  produced `19`. This tool request changed to `tool_choice=none` on replay
  and did not reuse KV; the separate text/image cache checks above did.
- Both retrieved `ORCA-583921` from a 28844-token uncached prompt. One
  paired request measured TTFT 18.16 / 17.62 seconds; this is a functional
  pair, not another three-pair speed claim or full-262K payload qualification.
- The separate continuation suite recorded 90/88 versus 99/97 MTP
  drafts/hits and 1 versus 0 quench events. Census/governor faults were zero.
  Image requests also exercised automatic quenching; those policy effects
  are not hidden inside the unprofiled text benchmark claims.

The larger retrieval prompt (twice as many background lines) after all six
image cases failed in the control. The first test guard stopped at 5.98 GiB
available / PSI 25.45%, using an older early-stop rule. Repeating with the
established `<4 GiB AND PSI >=30%` rule still crossed the independent 4 GiB
floor. The failure is retained as a baseline operating limit. Neither the
floor nor the original two-bank/context settings were relaxed; the bounded
28844-token fixture passed with matched fresh controls and candidates.

## Review correction: bank history replacement

Codex identified that bank copy and checkpoint restore retained vocabulary
hints from the destination's previous request. Repeated forks could grow the
shortlist toward the full vocabulary. Both paths now reset the count and GPU
upload cursor; the next feed rebuilds membership. A self-copy retains history.

The real-model regression failed before the fix, retaining 65813–65818 IDs
across repeated bank/checkpoint copies and a same-bank rewind. It passes
afterward, including removal of the old high-ID hint. The 400-row MTP prefix
comparison and 48 verify steps retain zero logit/state mismatches; two-bank,
disk-KV, partial-fork and graph-lifecycle gates also pass.

One fresh 8K/128-token pre-fix/fixed pair matched all 248320 logits and
128 generated IDs exactly. Prefill was 1438.46 / 1429.89 tok/s and decode
28.68 / 28.80 tok/s, with identical 51.81% acceptance, no quench and
2190 MHz clock medians. This regression pair does not replace the three-pair
adoption results above.

The fixed 262144-context, two-bank HTTP replay matched the pre-fix candidate
in all 11 continuation/tool/image/concurrency cases and five text cases
(ignoring generated tool-call IDs). Text/image cache hits remained 1463/794
tokens; census and governor faults were zero. Existing answer failures above
were unchanged.

65536 frontiers, 128 generated tokens, three alternating pairs, graphics

Bottleneck (nsys on the adopted MTP-vocabulary 8K profile): fused QSA
attention is 854.8 ms (10.2% of GPU kernel time, 52 launches, 16.4 ms

### QSA PV 6×2: rejected (no e2e gain)

The fused kernel's PV loop broadcast 12 probabilities to 256 threads
(about half of its shared-memory load wavefronts). The candidate maps
six heads × two dims per thread: half the probability broadcasts, two
value loads per thread, same per-(head, dim) FMA slot order.

`DS4_QWEN_QSA_PV6X2=1` selects it. Default remains 12×1. The fused vs
split kill switch `DS4_QWEN_QSA_NO_FUSED` is now read per dispatch; the
previous process-lifetime cache never switched kernels after the first
call.

Unit fixture (17 rows, 2050 selected tokens): PV 6×2 vs 12×1 is
bit-identical (max 0). Fused vs split: max 1.27e-7. Adjacent-row
selected Jaccard min 0.9688 / mean 0.9788 / max 0.9917.

Unprofiled A/B, control = 12×1, candidate = 6×2. Every pair matched all
248320 frontier logits and 128 generated IDs exactly.

### Selected-K/V row-pair reuse: rejected

Measured overlap was high enough to try a two-row block that gathers
once when 32-token tiles match. On the unit fixture it matched one-row
12×1 (max 0). On the real 8K fixture it did not: frontier max abs
0.73–1.37, RMS 0.15–0.17, same argmax, generated IDs first differed at
39/53. Prefill -1.52% / +0.22% / -0.92%; decode -2.12% / -2.75% /
+7.98%. Stopped before 64K. The kernel is not in the default binary
(`scratch/qwen-perf-20260914/qsa-pair-rejected.cu`).

### HC shared mix_down/inject: not implemented

Profile: mix_down+inject ~97 ms of 8403 ms GPU (1.2%). mix_down is
already a tensor-core GEMM; inject is 4 outputs. Combining them cannot
clear 2% e2e and would replace the fast mix_down. No A/B.

No production default changed. Diagnostic restores:
`DS4_QWEN_QSA_NO_FUSED`, `DS4_QWEN_QSA_PV6X2`, plus the earlier MTP
switches.
