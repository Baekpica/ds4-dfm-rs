# Qwen performance, 2026-09-14

This campaign references [qwen3.8-Flash-DGX](https://github.com/blazux/qwen3.8-Flash-DGX/tree/d542745cd41045bcd71b9d7dbe659bca014202bf).
Results below belong to the Base Q5 artifact and the stated workloads.
They do not qualify the Uncensored artifact or replace the older card sweep.

## Protocol

- Baseline code: `c40d3753d225e59b821834c6d948656841fedf47`.
- DGX Spark GB10, CUDA 13.3, `sm_121a`; user-managed 300–2200 MHz range.
  Graphics-clock medians were 2190 MHz in all speed pairs.
- Base `MQ-Q5-SSD-PLE-BF16` weights with the FP8 E4M3FN PLE sidecar,
  2 GiB PLE cache, 16 workers, 8192 prefill cap, MTP draft 2.
  One resident VMM owner; each measurement used a fresh guarded worker.
- Exact `speed-bench/promessi_sposi.txt` fixture, SHA-256
  `f53e0d80cb2d4492d24ebd63c7000c397b16ae70f9bf09b3763e5d8323ec209f`.
  Independent 8192/65536 frontiers, 128 generated tokens, three alternating
  A/B pairs per frontier. Benchmark generation excludes EOS, as before.
- Adoption threshold: >=2% end-to-end gain without a repeatable >2% loss
  in another principal metric. Profiled timings are diagnostic only.

## MTP output vocabulary

The draft scores the first 65536 BPE IDs, non-normal token types and IDs
observed by its shifted input stream. The target output and verification
remain full vocabulary. No weight conversion or extra model file is needed.
The list occupies at most one vocabulary-sized GPU ID array, a host ID array
and a byte membership map per graph. It resets with the graph; it is a
proposal hint, separate from accepted KV state. A restore can change proposals.

GPU argmax alone was rejected: 8K decode medians were 27.87 versus
28.00 tok/s (+0.47%), below the threshold. Its compact-result helper is used
by the separately measured vocabulary reduction.

All rates below are tok/s. A uses the full head and CPU selection; B uses
the compact head and GPU selection.

| 8k | 2 | 1413.73 | 1415.36 | 27.96 | 28.78 |

Median decode gains: **3.04% at 8K**, **3.87% at 64K**. Median prefill
changes: -0.10% and -0.14%. No speed-run MTP quench occurred.
At 8K, draft acceptance moved from 53.66% to 51.81%, while mean cycle time
was about 52.93 versus 50.67 ms. Report both: acceptance alone hides the gain.

The diagnostic CUDA profiles show a full 248320-row Q8 vector head around
2.69 ms and the roughly 66.7K-row candidate head around 0.80 ms. Profiling
changed the baseline's speculative scheduling, so its aggregate decode
rate is not used for adoption.

### Correctness and HTTP checks

- Every 8K and 64K pair matched all 248320 prefill logits and all 128
  generated token IDs exactly. This is evidence for these fixtures, not a
  claim that a changed draft is bit-identical on every mixed-quant workload.
- Draft-selection boundaries: low-index ties, NaN, infinity, all-masked
  sentinel, compact high-ID remapping, duplicate and invalid IDs passed.
- 48 native verify steps: 32 accepted / 16 rejected drafts, zero logit or
  state mismatches. Two-bank, disk-KV, partial-fork and graph-lifecycle gates
  passed independently.
- Three fresh HTTP worker pairs (two banks, 8192 context, greedy, thinking
  disabled) produced identical Korean extraction, Python code, tool JSON,
  Korean time-arithmetic and English scheduling responses. Code passed
  empty, duplicate and mixed-hashable input checks.
- Both controls and candidates answered the time arithmetic incorrectly
  (`11:45`, expected `11:50`). Both wrapped the correct English JSON in a
  Markdown fence. Those baseline failures were retained, not counted as
  newly successful quality cases.
- HTTP TTFT median increases were 0.24–0.82% across four prompts; the time
  arithmetic prompt decreased 1.23%. Total request time decreased 1.62–3.32%.
  A separate metrics probe confirmed 62 drafts / 62 hits, no quench and
  zero census/governor faults; its timings are not additional speed evidence.

Diagnostic controls: `DS4_QWEN_MTP_FULL_VOCAB=1` and
`DS4_QWEN_MTP_CPU_ARGMAX=1`. Raw receipts and captures are under local
`scratch/qwen-perf-20260914/`; this report preserves the reviewable summary.

## QSA Tensor Core experiment: rejected

Two prefill-only BF16 QK/PV implementations retained FP32 cache storage,
softmax and output accumulation. Both passed an independent rounded-input
attention reference (max error about 5.6e-7), masked/tail cases and the
unchanged FP32/decode checks.

| 8K candidate | Prefill tok/s |
|---|---:|
| Existing FP32 fused QSA | 1418.32 |
| 64-slot tiles, 128 threads | 725.83 |
| Padded 32-slot tiles, 256 threads, reused scratch | 1224.59 |
| Fresh FP32 control after both experiments | 1423.31 |

The first kernel had only four active warps/SM and about 69% excessive
shared-memory wavefronts. Reusing QK/PV scratch and padding the shared tiles
reduced that cost, but the second implementation still regressed prefill
about 14%. These obvious regressions were stopped before an adoption sweep.

Full-model 8K prefill logits changed: max absolute error 1.02–1.16,
RMS 0.175–0.201; the frontier argmax stayed the same, while generated tokens
first differed at offsets 41/39. Kernel-reference agreement alone therefore
was not a full-model parity claim. No broad quality qualification is claimed
for these discarded candidates. The production QSA implementation is intact.

Both patches and diagnostics remain in the local campaign directory as
`qsa-tc-v1.patch`, `qsa-tc-v2.patch` and `qsa-tc-*.ncu-rep`.
The initial NCU run used default clock control and reported 2.42 GHz; it is
not speed evidence. Subsequent NCU runs explicitly use `--clock-control none`.
The unprofiled A/B graphics-clock medians remained 2190 MHz.

## PLE descriptor pool experiment: rejected

A four-slot mapped host descriptor pool replaced per-gather allocation and
descriptor copies. Lease-release callbacks returned slots without CUDA API
calls. The two-stream, page-crossing and minimum-cache fixtures passed,
including more than four tiles to exercise reuse.

| Context | Prefill control / pool | Decode control / pool |
|---|---:|---:|
| 8K | 1425.04 / 1421.18 | 28.63 / 27.73 |
| 64K | 1515.04 / 1515.01 | 29.61 / 27.51 |

Each row is one fresh A/B pair with the adopted MTP vocabulary path.
All frontier logits and 128 generated IDs matched exactly. Acceptance was
unchanged, no quench occurred, and clock medians were 2190 MHz.
At 8K, PLE enqueue time fell from 17 to 6 ms over the run, but prefill
did not improve and decode regressed 3.14% / 7.09%. The candidate was stopped
before an adoption sweep. The original PLE path remains; the discarded patch
is `scratch/qwen-perf-20260914/ple-pool-rejected.patch`.
