# GLM VQ nonexpert Q4_K candidate

Q4_K is being evaluated for execution speed. A smaller artifact alone is
not an adoption criterion: restoring Q4 to BF16 before GEMM was slower
than the original precision path in the first matched observation.

`q4_k_nonexpert_v2` changes only eligible nonexpert trunk matrices:
attention projections, the first three dense FFNs, embedding and output
head. Routed and shared experts, codebooks, router/state controls, MTP
and vision keep their source bytes. `--keep TENSOR` retains selected
eligible matrices in their source precision. The loader rejects Q4_K
outside this allowlist; the earlier experimental v1 recipe is retired.

The initial v2 candidate changes 202 matrices; the other 39,660 tensor
hashes are unchanged. The parent manifest is
`c3c35fe33c2ac7075f2b46ef234179b0521e2a3b590d71e3ba1e367917d201cf`;
the candidate manifest is
`cbc2366656f40d973f76b0d1c3bb8fce3f4c53e050068945f01a5a500d196caf`.
These identify the same original revision and VQ expert bytes, not an
Uncensored or differently trained control.

Build the CPU quantizer with `make gguf-tools/libds4q.so`, then run
`tools/glm_vq_q4k.py SOURCE NEW_OUTPUT --workers 12` in a NumPy environment
under the documented memory guard. The destination must not exist.
Conversion restores original FP8 block scales and BF16 rounding before
standard 256-element/144-byte Q4_K quantization. It uses no importance
matrix. Unchanged parts are hardlinked; rewritten tensors retain parent
hashes and the recipe records converter/quantizer hashes. Do not modify
hardlinked files in either artifact.

## Execution and numerical contract

The retained whole profile attributed 44.97% of decode time to
dense/shared/control operations. KDA Q/K/V/O alone require 8.5 GiB of
logical BF16 weight reads per decoded token; Q4_K reduces that to
2.391 GiB. This is a bandwidth opportunity,
not a measured whole-model speedup by itself.

Widths 1–8 use direct Q4_K dots without global BF16 weight restoration.
Wider matrices use the existing Q4_K/Q8_1 MMQ primitive. Output retains
the GLM BF16 boundary. Compared with restore+cuBLAS, direct dots avoid
BF16 weight rounding; MMQ additionally quantizes activations to Q8_1.
These arithmetic changes must be assessed separately from weight loss.
The initial direct kernel uses 40 registers and no local memory/spills.

`DS4_GLMVQ_Q4_DIRECT=0` selects the same-weight BF16 restore+cuBLAS
diagnostic. Its scratch quote includes expanded Q4 output-head weights;
the default direct path retains the existing quote. This fixes a missing
head reservation found before the fallback quality run produced outputs.
The direct path does not imply CUDA graph or MTP qualification.

Focused gates passed: role/shape/finite-scale validation, FP8 scale axes
and converter packing, exact preservation of a selected FP8 tensor and
its link, 15 direct-dot geometry/width cases, 20 production adapter cases,
embedding gather, and 37,976 matrix scratch requirements across six
context/width regimes. Independent FP64 references use operation-dependent
FP32 accumulation and BF16 half-ULP bounds. The MMQ plumbing fixture uses
exactly Q8-representable inputs to isolate layout from activation loss.

## Adoption boundary

The 2026-10-16 exploratory comparison uses a 200-matrix v2 candidate
that retains the original embedding and output head. Its manifest is
`d16712edb7940dd070873d7aa660f7731c036605484a1bc54155e5f5c802fe47`.

| One fresh process per arm | Prefill tok/s | Decode tok/s |
|---|---:|---:|
| Original nonexpert precision | 123.39 | 3.58 |
| Q4_K restored to BF16 + cuBLAS | 111.37 | 3.05 |
| Q4_K direct dot / wide MMQ | 122.48 | 3.88 |

All three use binary SHA256
`5fbab3649a214edc55c350a351f31cf31afd6b385e7de4a5226423feb274b546`,
source `923e9b34`, the same 1,984-token raw code prompt and 32 generated
transitions, context 2,048, chunk 512, MTP/capture/MMA off. The direct
candidate is 8.4% faster in decode in this observation; prefill is similar.
These single samples motivate kernel profiling, not adoption. Kernel
transport optimizations require repeated matched A/B before promotion.
The [cooperative-load investigation](glm53-vq-q4-stream-2026-10-16.md)
records the subsequent kernel and whole-path evidence.

All arms produced finite frontier logits and the same 32 IDs. This sharply
peaked code frontier does not resolve the separate text-quality failures:
both v2 candidates generated unsolicited tool markup and degenerate text
on the Korean-summary case. The original also failed that case's formatting
and length contract, but retained Korean text. The other five small-screen
task contracts held. Mean target NLL changed by +0.02164 nat/token for all
202 matrices and +0.01090 for KeepHead over 106 targets. Neither short
token identity nor a small aggregate loss excuses the observed regression.

Output-quality adoption remains pending for v2.
The retired 328-matrix v1 also quantized shared experts. Its six-case
screen showed a Korean-summary language regression and mean target NLL
increase of 0.02479 nat/token over 106 targets. Other five task contracts
held. That result is not evidence for v2, and v1 was not adopted.

The original precision controls remain reusable; passing unchanged
packing and primitive gates are not repeated. Select precision within
the nonexpert allowlist using output quality and matched whole-workload
prefill/decode measurements. Short greedy agreement alone is insufficient.
